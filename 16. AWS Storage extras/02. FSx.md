# FSx

- 3rd party high-performance file systems
- Fully managed service
- Types:
  - FSx for...
    - Lustre
    - Windows file server
    - NetApp ONTAP
    - OpenZFS
- FSx is a family of fully managed file services designed for:
  - specialized file workloads
  - proprietary protocols
  - high-performance computing [HPC] that standard EFS or EBS can't handle

> While EFS is built for standard linux [NFS/POSIX] shared file system, FSx is a multi-product umbrella for more specialized files

There are 4 flavors of FSx

- FSx for windows file server
  - lifting and shifting native windows applications, user home directories, or shared corporate drives that require windows ACLs, NTFS permissions, and Active Directory Integration
- FSx for Lustre
  - high-performance computing [HPC]
  - machine learning model traning
  - financial risk modeling
  - video rendering
  - processes petabytes of data at blazing-fast speeds
  - can link directly to S3 bucket as a backing store [reading data from S3 and writing it back]
- FSx for NetApp ONTAP
  - enterprise migrations where customers already use NetApp hardware on-premises and want enterprise features like instant data cloning, advanced deduplication, compression, and snapshotting in the cloud
- FSx for OpenZFS
  - high-performance linux workloads requiring native ZFS features, such as sub-millisecond latencies, point-in-time snapshots, file cloning, and compression

- Windows file share / Active directory / SMB -> FSx for windows file server
- High-performance computing / machine learning / lustre / fast s3 integration -> FSx for Luster
- Linux shared file system / POSIX / Wordpress multi-instance -> EFS
- Block storage for a single EC2 instance -> EBS

## FSx for windows

- Fully managed windows file system share drive
- Supports SMB protocol and windows NTFS
- Microsoft active directory integration, ACLs, user quotas
- Can be mounted on LINUX EC2 instances
- Supports Microsoft's Distributed file sytem [DFS] namespaces

- Scale up to 10s of gb/s, millions of IOPS, 100s PB of data
- Storage options
  - SSD: latency sensitive workloads [dbs, media processing, data analytics, ...]
  - HDD: broad spectrum of workloads [home directory, CMS,...]
- Can be accessed from on-premise infra [VPN or Direct Connect]
- Can be Multi-AZ
- Data is backed-up daily to S3

## FSx for Lustre [Linux + Cluster]: Computer-intensive workloads

- Type of parallel distributed file system, used for large-scale computing
  z- Lustre = Linux + Cluster
- Use for:
  - machine learning
  - high-performance computing [HPC]
  - video processing
  - financial modeling
  - electronic design automation
- Scales to 100s gb/s, millions of IOPS, sub-ms latencies
  - it can process massive datasets at blazing-fast speeds [hundreds of gigabytes per second]
  - integrates natively with S3
- Storage options
  - SSD: low-latency, IOPS intensive workloads, small & random file operations
  - HDD: throughput-intensive workloads, large & sequential file operations
- Seamless integration with S3
  - can "read s3" as a file system [through FSx]
  - can write the output of the computations back to S3 [through FSx]
- Can be used from on-premise servers [VPN or Direct Connect]

## FSx File System deployment options

- Scratch file system
  - temporary storage
  - data is not replicated [doesn't persist if file server fails]
  - high burst [6x faster, 200mbs per TB]
  - usage: short-term processing, optimize costs

```
region
|AZ 1                          |
  compute instances --- ENI    |-------------------- [AZ 2 compute instances]
                         |     |
                        FSx    |--------------- S3 bucket
               [FSx for Lustre |              [optional data repo]
             Scratch file system
                 DB temp]      | // data isn't replicated
```

- Persistent file system
  - long-term storage
  - data is replicated within the same AZ
  - replace failed files within minutes
  - usage: long-term processing, sensitive data

```
region
|AZ 1                          |
  compute instances --- ENI    |-------------------- [AZ 2 compute instances]
                         |     |
                        FSx    |--------------- S3 bucket
               [FSx for Lustre |              [optional data repo]
             Persistent file system] // data is replicated
```

## FSx for NetApp ONTAP

- Managed NetApp ONTAP on AWS
- File system compatible with NFS, SMB, iSCSI protocol
  - NFS: linux
  - SMB: windows
  - iSCSI: block storage workloads
- Move workloads running on ONTAP or NAS to AWS
- Works with: linux, windows, macos, vmware cloud on aws, amazon workspaces & appstream 2.0, ec2, ecs, eks
- Storage shrinks/grows automatically
- Snapshots, replication, low-cost, compression and data de-duplication
- Point-in-time instantenous cloning [helpful for testing new workloads]

```
        [FSx for NetAPP ONTAP]
                |
                | NFS, SMB, iSCSI
                |
    | EC2    ECS     EKS      Linux/Windows/MacOs |
    | VMWare cloud on AWS     On-premise server   |
    | Appstream 2.0           WorkSpaces          |
```

## FSx for OpenZFS

- Manage OpenZFS file system on AWS
- file system compatible with NFS [v3, v4, v4.1, v4.2]
- Move workloads running on ZFS to AWS
- Works with: linux, windows, macos, vmware cloud on aws, amazon workspaces & appstream 2.0, ec2, ecs, eks
- Up to 1M IOPS with < 0.5ms latency
- Snapshots, compression and low-cost
- Point-in-time instantaneous cloning [helpful for testing new workloads]
