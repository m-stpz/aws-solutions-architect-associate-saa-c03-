# Transfer family

- Fully-managed service for file transfers into and out of S3 or EFS using the FTP protocol
  - When a client upload a file through a transfer family server, it lands natively in one of two storage backends
    - S3
      - files appear instantly as standard s3 objects
      - allows downstream data lakes, lambda functions, or analytics pipelines to process them immediately
    - EFS
      - files are written directly to a shared POSIX-compliant file system
      - accessible by EC2 instances or containers

- Supported protocols: AWS transfer for..
  - unencrypted
    - FTP [File Transfer Protocol]: plain text FTP
      - secure alternatives are heavily preferred
  - encrypted in-flight
    - FTPS [File Transfer Protocol SSL/TLS]
    - SFTP [Secure File Transfer Protocol]: most common protocol for secure file transfer over SSH
- Managed infrastructured, scalable, reliable, highly available [multi-AZ]
- Pay per provisioned endpoint per hour + data transfers in GB
- Store and manage user's credentials within the service
- Integrate with existing auth systems
  - MS Active Directory, LDAP, Okta, Amazon Cognito, custom
- Usage: sharing files, public datasets, CRM, ERP, ...

## Transfer family vs Storage Gateway

- Transfer family: cloud-native file transfer
  - use this when external 3rd-party vendors, clients, or partners need to drop files over SFTP/AS2 directly into our s3 bucket/efs share in the cloud
  - no on-premise hardware required

- Storage gateway: hybrid cloud integration
  - use this when our own on-premises data center or local servers need to interact with AWS storage
  - uses local protocols [NFS/SMB, iSCSI] via physical/virtual application deployed on-site
