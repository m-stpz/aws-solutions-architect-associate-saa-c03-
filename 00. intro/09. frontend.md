# Frontend and AWS

If the backend lives on ec2 instances or lambda, and the db on RDS, where would the frontend lives?

- It depends the type of frontend: SPA or Server-side rendered?

1. Static SPA (Cloud-Native Standard)

- For modern client-side frameworks, the frontend doesn't need compute server
- Then S3 is perfect for that
  - distributes globally through Amazon CloudFront (CDN)

- How it works
  - browser requests the frontend from CloudFront/S3 (near zero-latency, infinite scaling, highly cost-effective)
  - Downloaded JS runs inside the user's browser
  - Frontend makes async API calls directly to the backend living on E2 fleet behind an ALB

```
[ Browser ] ──1. Loads HTML/JS/CSS──► [ CloudFront + S3 ] (Frontend)
     │
     └──2. Calls API (/api/v1)─────► [ ALB ] ──► [ EC2 Fleet ] ──► [ RDS ]
                                                 (Backend)         (Database)
```

2. Server-side Rendered [SSR] or monolith

- For applications where the server dynamically constructs the HTML per request (ex: Next.js, SSR, Django templates, Rails, PHP/Wordpress, Laravel, Express with EJS):
  - Then, it lives on an EC2 instance alongside, or running as, the backend application

- How it works
  - user requests page through route 53 and the ALB
  - EC2 instances query the RDS db, injects data into the HTML template on the fly and returns the fully rendered HTML document back to the browser

## Rule of thumb

- Static builds: store in s3 + cloudfront
- Server-side: host on EC2 instance
