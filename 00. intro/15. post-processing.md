# Post-processing: Decoupled heavy, async media transformations from user request

## S3 Authentication for users: Cognito identity pools vs. S3 pre-signed URLs

- Both approaches allow clients to transfer files directly to s3 without passing byte streams through API gateway or lambda

| Aspect              | S3 Pre-signed URLs / POST Policies                      | Cognito Identity Pools                              |
| ------------------- | ------------------------------------------------------- | --------------------------------------------------- |
| How it works        | Lmabda generates a signed, temp URL                     | User token is exchanged for AWS IAM creds           |
| Client overhead     | Zero AWS SDK required. Client executes standard `fetch` | Heavy client footprint: client must install AWS SDK |
| Backend gatekepping | Strcit per-request control                              | Once credentials are issues, client can mess around |
| Blast radius        | Single-file scope                                       | Broad folder scope                                  |

When to choose S3 pre-signed URL?

- public web / mobile apps / standard saas and blogs
- tight backend control
- strict file size and MIME constraints
- typical user interactions: updating avatar, attaching image to blog, submitting resume

When to choose cognito identity pools?

- interactive file management [Cloud Drive/Dropbox UX]
  - user wants to browse, created nested subfolders, rename, delete and move multiple files
  - multiple operations without triggering an API call for each
- multi-service necessity on AWS: client needs temp IAM permissions to interact with other AWS services, beyond s3
- high-frequency multi-file ingestion
