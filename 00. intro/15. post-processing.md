# Post-processing: Decoupled heavy, async media transformations from user request

Decoupling heavy, async media transformations from client requests is a standard distributed system pattern

- HTTP req/res handles metadata and access control
- resource-intensive pipelines run in the background

## Architectural flow

1. Upload handshake
   - client requests permission to upload
   - API generates a pre-signed/temp upload authorization
2. Direct-to-storage upload
   - client pushes bytes directly to object storage
   - it bypasses API application servers entirely
3. Event notification and queueing
   - storage emits an "object created" event to a durable message broker
4. Buffered worker consumption
   - workers pull tasks from the queue
5. Execution and artifact storage
   - worker performs transformation
6. Client notification

## 1. Eager async pipeline [S3 event + lambda]

- Used when every uploaded image has
- Runs immediately after upload, computing a fixed set of predefined variants

1. Write an initial record with status indicator `PENDING`
2. Once the async processing finishes, it updates the record with the generated assets URLS and marks it complete

```

client ---> PUT image
                |---> dynamodb: create entry
                |               s3:ObjectCreated:Put
                |---> S3: raw-images/ -------> Lambda ----> s3: processed-images/<thumb>
                                                          |----> dynamodb: update entry
```

- Avoid lambda loops: Separate source and destination
  - either use 2 separates buckets [raw vs. processed]
  - or isolated prefixes
    - triggers only on `raws/*`
    - writes to `processed/*`
  - else, it can create a loop
- Decoupling: for high upload spikes, place an SQS queue between S3 event notification and lambda processing to throlle concurrency

```
  ObjectCreated
s3 ----------> SQS ----> Lambda
```

## 2. On-demand dynamic resizing at the edge [modern cloud-native standard]

- High-scale media sites
- Instead of pre-generating thumbnails for every upload, thumbs are generated only when requested by a viewer and cached at CloudFront
