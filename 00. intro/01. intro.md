- How to choose an AWS Region?
  - Compliance: data governance and legal requirements
  - Proximity to customers: reduced latency
  - Available services within a region
  - Pricing: it varies from region to region

- AWS Availability zones
  - Each region has zones (usually 3 - min 3/max 6)
  - Each availability zone (AZ) is one or more discrete data centers with redundant power, networking, and connectivity
  - Each zone is separate from each other, so they're separated from disasters
  - They're connected with high bandwidth, ultra-low latency networking

- AWS Points of presence (Edge locations)
  - 400+ points of present (400+ edge locations & 10+ regional caches)
  - 90+ cities across 40+ countries
  - Content is delivered to users with lower latency

## Understanding AZ (Availability Zones)

- AZ is one physically isolated data centers located within a specific AWS Region

### Region vs. AZ

- AWS Region: a geographic cluster somewhere (e.g., `us-east-1` in N. Virginia, `eu-central-1` in Frankfurt)
- Availability zone: a physically separated data center location inside that region
  - Every AWS region contains at least 3 AZ
  - ex: `eu-central-1a`, `eu-central-1b`, `eu-central-1c`

- Region name: human readable
- Region code: short string combining region, direction and number
- AZ: appends a letter to the region code
- e.g. Europe (Frankfurt)
  - region code: `eu-central-1`
  - az names:
    - `eu-central-1a`
    - `eu-central-1b`
    - `eu-central-1c`

### Characteristics of an AZ

- Physically separated: AZs within the same region are close enough for low latency, but far enough that localized problems won't affect multiple ones
- Each AZ has its own independent utility power grid, backup generators, cooling systems and physical security
- Connect via ultra-low latency fiber: All AZs in a single region are interconnected with redundant, high-throughput fiber networks

### Why do they exist?

- High availability and Fault tolerance
- You deploy your resources in a Multi-AZ setup

1. sping two web servers: `AZ-a` and `AZ-b`
2. Place a load balancer in front of them
3. Traffic is split

- AZ-Specific services (you must choose an AZ):
  - EC2 instances
  - EBS volumes
- Regional services
  - S3
  - EFS
  - DynamoDB

- For 99% of web applications, place your EC2s in different AZs, but in the SAME region, rather than spreading them across multiple regions
  - Multi-AZ, but same region
  - when do people use multi-region?
    - global performance
    - extreme disaster recovery
