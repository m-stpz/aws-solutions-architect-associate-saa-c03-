# Storage on AWS

## Core types

| Storage type         | Category                  | Primary use case                                                                | Key constraints / exam triggers                                               |
| -------------------- | ------------------------- | ------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| EBS                  | Block storage             | Root volumes, dbs                                                               | attached to a SINGLE EC2 instance WITHIN one AZ                               |
| EFS                  | File storage              | Shared linux file systems, web server content [wordpress multi-az], CMS data    | POSIX-compliant, mountable by N EC2 instances. Multiple AZs                   |
| S3                   | Object storage            | static websites, data lakes, backups, archives, media                           | key-value store. HTTP/Rest API, 11 9's durability. unlimited scale            |
| FSx                  | Specialized files         | Windows SMB, high-performance computing, enterprise NAS                         | Used when EFS or EBS can't support specialized protocols/enterprise file apps |
| FSx for windows      | file storage [SMB]        | windows home directories, shared corporate drives, active directory integration | NTFS permissions, SMB protocol, windows lift-and-shift                        |
| FSx for Lustre       | file storage [high-speed] | HPC, machine learning, video rendering, massive analytics                       | Parallel distributed file system, native integration with s3 [read/write]     |
| FSx for OpenZFS      | file storage [NFS]        | high-performance linux workloads, low-latency dbs, code repos                   | sub-ms latency, ZFS point-in-time snapshots, rapid cloning, ZSTD compression  |
| FSx for NetApp ONTAP | Enterprise NAS            | enterprise cloud migrations, mixed windows/linux envs, advanced data management | NetApp ONTAP features, instance zero-space data cloning                       |

## Concepts

- Multipart upload
  - required files > 5gb
  - recommended for file > 100mb
  - parallel chunk upload
  - granular retries

- Byte range fetch:
  - downloads specific byte offsets [e.g. first 250bytes]
  - no need to fetch whole file
  - massive network savings for indexing large files

- Storage classes and analytics
  - s3 analytics determines optimizal transition days
  - lifecycle rules + transition actions
    - lower cost and expiration actions to delete old object verions

- Security and access control
  - OAC [Origin Access Control]
    - secure s3, so only CloudFront can read the bucket data
  - Object lock
    - locks objects indefinitely
    - manually changeable
