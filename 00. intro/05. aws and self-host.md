# AWS and self-host

- How can we run our infra on AWS?
  - Yes, we can
- It's possible to remain vendor independent even when using AWS

## How to stay vendor-free on AWS

- Use AWS purely as raw compute, storage, and networking hardware

1. Use plain VMs (EC2) with containers
   - run the app inside docker containers orchestrated via docker compose or k8 on standard EC2 instances
   - avoid serverless options tied to AWS APIs (like AWS lambda)

2. Self-host dbs and caches: install open-sources db directly on EC2 instances or containers instead of using managed engines like DynamoDB or Aurora

3. Standard protocols for storage: if you use S3 for file storage, use standard S3-compatible SDKs

4. Infrastructure as code (IaC): Write deployment automation using terraform instead of AWS CloudFormation

This way, the AWS setup is just linux boxes, which can be migrated to another host (Hetzner, DigitalOcean, or bare metal)

## Is AWS the cheapest?

- AWS is rarely the cheapest option to host raw VWs though
- Other options (DigitalOcean, Linode, Hetzer) provide equivalent vCPU/RAM for 30% to 70% less than AWS standard EC2 on-demand rates
