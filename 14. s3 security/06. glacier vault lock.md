# Glacier Vault Lock

- Adopt a WORM model
  - WORM = write once, read many
- Create a vault lock policy
- Locks the policy for future edits [can not longer be changed/deleted]
- Helpful for compliance and data retention

## S3 Object lock

- Versioning must be enabled
- Block an object version deletion for a specified amount of time
  - applied at the OBJECT LEVEL, not BUCKET LEVEL

- There two types of retention mode:

1. Compliance [very restrict]:
   - object versions can't be overwritten/deleted by ANY user, INCLUDING the ROOT
   - object retention modes can't be changed, and retention periods can't be shortened

2. Governance [more lenient]:
   - most users can't overwrite/delete an object version, or alter its lock settings
   - some users have special permissions to change the retention/delete object

- Retention period: project the object for a fixed period, it can be extended
- Legal hod:
  - protect the object indefinetely, independent from retention period
  - can be freedly placed/removed using the `s3:PutObjectLegalHold` IAM permission
