# Neptune

- Fully managed graph db
  - graph usage:
    - social network
- Highly available across 3 AZ, up to 15 read replicas
- Build and run applications working with highly connected datasets
  - complex and hard queries
- Can store up to billions of relations and query the graph with ms latency
- Highly available with replication across multiple AZs
- Great for:
  - knowledge graphs [wikipedia]
  - fraud detection
  - recommendation engines
  - social networking

## Streams

- Real-time ordered sequence of every change to graph data
- Changes are available immediately after writing
- No duplicates, strict order
- Streams data is accessible in an HTTP REST API
  - ec2, lambda, etc can query it
- Use cases:
  - send notifications when changes are made
  - maintain graph data sync in another data store, ex: s3, opensearch, elasticache
  - replicate data across regions in neptune

```
neptune cluster <--- writes
    |
neptune streams
    |
    | Streams API: HTTP GET Req
[ec2, lambda...]
    |
    |---- s3
    |---- opensearch
    |---- elasticache
```
