# Choosing the right db

- It comes down to:
  - data structure
  - access patterns
  - latency targets
  - scaling model

> For more info see `databases in aws/00. criteria choosing a db`

Questions to choose the right db based on your architecture:

- Read-heavy, write-heavy, or balanced workload?
- What's the throughput need? Will it change, does it need to scale/fluctuate during the day?
- How much data to store and for how long? Will it grow?
  - average object size?
  - how are they accessed?
- Data durability? Source of truth for the data?
- Latency requirements? Concurrent users?
- Data model? How will you query the data?
  - joins? structured? semi-structured?
- Strong schema? More flexibility? Reporting? Searching? RDBMS/NoSql
- License costs? Switch to cloud native db such as Aurora?

## Db Types

- RDBMS [SQL/OLTP]: great for joins
  - RDS, Aurora
- NoSQL db - no joins, no SQL
  - dynamodb [json]
  - elasticache [key/value pairs]
  - neptune [graphs]
  - documentdb [for mongodb]
  - keyspaces [apache cassandra]
- Object store:
  - S3 [big objects]
  - glacier [backups/archives]
- Data warehouse [sql analytics/BI]
  - redshift [OLAP]
  - athena
  - EMR
- Search: free text, unstructured searches
  - OpenSearch[json]
- Graphs: displays relationships between data
  - neptune
- Ledger: quantum ledger db
- Timeseries: amazon timestream
