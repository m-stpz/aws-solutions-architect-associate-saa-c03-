# RDS

- managed postgresql, mysql, oracle, sql server, db2, mariadb, custom
  - insrtead of installing and patching db software manually on bare services, AWS manages the setup
  - aws takes care of routine OS patching, automated bug fixes, and underlying infra

- provisioned RDS instance size and EBS volume type and size
  - compute [instance size]: pick how much CPU and RAM the db runs on, ex: `db.t4g.micro`, `db.r6g.xlarge`
  - storage [EBS volume and size]: data lives on attached network storage [EBS]
    - choose the size and disk performance tier

- auto-scaling capability for storage
  - if db approaches storage limit, RDS automatically allocates more disk space in the background, without taking the db offline
  - prevents crashes caused by "disk full" errors during unexpected data growth

- support for read replicas and multi AZ
  - read replicates [performance/scaling]
    - async copies of primary db
    - direct all `SELECT` read queries to replicates to take read load off the primary writer db
    - if primary fails, read replica can be manually promoted to new primary
  - multi-AZ [disaster recovery/high availability]
    - a sync copy is kept in a different physical data center [AZ]
    - can't read from/write to the standby
    - if primary db suffers outage, RDS executes automatic failover to the standby in ~60-120s with zero data loss

- security through IAM, security groups, KMS, SSL in transit
  - IAM auth: users and services [ex: lambda/ec2] can log in using short-lived IAM tokens rather than hardcoded db passwords
  - security groups: act as a virtual firewall, restrict access to only specific IPs or application servers can reach the db port
  - KMS [key management service] encryption at rest
  - SSL/TLS in transit: enforces encrypted data flow across the wire between application and db

- automated backup with point in time restore feature [up to 35 days]

- manual db snapshot for longer-term recovery
  - user-triggered, persist indefinitely, even if RDS instance is deleted
  - compliance, major release checkpoints, long-term archiving

- managed and scheduled maintenance [with downtime]
- support for IAM auth, integration with secrets manager
- RDS custom for access to and customize the underlying instance [oracle & SQL server]

- use case: store relational datasets [RDBMS/OLTP], perform SQL queries, transactions
