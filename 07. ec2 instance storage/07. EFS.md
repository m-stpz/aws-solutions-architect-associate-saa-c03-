# EFS - Elastic File System

- Managed NFS (network file system) that can be mounted on many EC2
- EFS works with EC2 instances in multi-AZ
- Highly available, scalable, expensive (3x gp2), pay per use

```
ec2_ins_us_east_1a     ec2_ins_us_east_1b   ec2_ins_us_east_1c
    \                        |               /
[               efs filesystem               ]
```

- Use cases:
  - content management
  - web serving
  - data sharing
  - wordpress

- Uses:
  - NFSv4.1 protocol
  - security group to control access to EFS
  - POSIX file system (~Linux) that has a standard file API
  - Encryption at rest using KMS

- Compatible with Linux based AMI (not windows)
- File system scales automatically
  - pay-per-use
  - no capacity planning

## Performance and storage classes

- EFS Scale
  - 1000s of concurrent NFS clients, 10 gb+/s throughput
  - grow to petabyte-scale network file system, automatically

- Performance mode (set EFS creation time)
  - General purpose (default): latency-sensitive use cases (web server, CMS, etc)
  - Max I/O: higher latency, throughput, highly parallel (big data, media processing)

- Throughput mode
  - Bursting: 1TB = 50mb/s + burst of up to 100 mb/s
  - Provisioned: set throughput regardless of storage size, ex: 1 gb/s for 1 TB storage
  - Elastic: automatically scales throughput up/down based on workloads
    - up to 1gb/s reads and 1gb/s writes
    - used for unpredictable workloads

## EFS Storage classes

- Storage tiers (lifecycle management feature - move file after N days):
  - standard: frequently accessed
  - infrequent access (EFS-IA): cost to retrieve files, lower price to store
  - archive: rarely accessed data (few times each year), 50% cheaper
  - implement lifecycle policies to move files between the tiers

- Availability and durability
  - standard: multi-AZ, great for prod
    - use this in prod
  - one zone: great for dev, backup enabled by default, compatible with EFS-IA

## EFS vs. EBS vs. CloudFront

- EBS and EFS are cloud storage services that hold data for compute instances
- CloudFront is a CDN to distribute content to end-users globally

- EBS: Virtual dedicated hard drive attached to ONE machine in ONE AZ
  - one instance (except multi-attach `io1`/`io2`)
  - are locked at the AZ level
  - gp2: IO increases if the disk size increases
  - gp3 and io1: can increase IO independently

  - to migrate EBS volume across AZ
    1. take a snapshot
    2. restore snapshot into another AZ
    3. EBS backups use IO, so you shouldn't run them while application is handling traffic
  - root EBS volumes of instances get terminated by default with the EC2 instance termination (can be disabled)

- EFS: Shared drive that thousands of instances across MULTIPLE AZs can read/write simultaneously
  - mounting 100s of instances across AZ
  - EFS share website files
  - only for linux instances (POSIX)
  - EFS $ > EBS $
  - can leverage storage tiers for cost reduction

- CloudFront: caching layer spread across hundreds of edge locations worldwide

## Creating and Using the EFS

1. create efs file system

- efs / Create file system
- select name and VPC
- select storage class
  - standard
  - one zone
- create

2. config security groups

- EC2 console / security groups
- create an EFS security group
- add inbound rules
- attach the security group to EFS mount targets

3. create ec2 instances with efs

- create the ec2 instance
  - on the network settings, select a subnet
- on EBS volumes, select file systems
