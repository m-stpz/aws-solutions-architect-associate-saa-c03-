# EC2 Instance Store

- EBS volumes are network drives with good, but limited performance
- Do you need high-performance hardware disk? Use EC2 instance store

Pros:

- Better I/O performance
- Good for buffer/cache/temporary content

Cons:

- They lose their storage if they're stopped (ephemeral)
- Risk of data loss if hardware fails
- Backups and replications are your responsibility

## Instance store vs. EBS (Elastic Block Store)

- EBS:
  - like a network hard drive (NAS)
  - lives on a separate rack accross the data center
  - connects to your instance over a fast network

- Instance store:
  - physical hard drive (SSD)
  - literally on the same server rack where the virtual CPU and RAM live

| Characteristic                  | EBS                                                            | Instance store                                              |
| ------------------------------- | -------------------------------------------------------------- | ----------------------------------------------------------- |
| Data lifespan                   | Persistent. Data is independent from the EC2                   | Ephemeral. If you stop or terminate instance, data is wiped |
| Performance (speed and latency) | Small network overhead. Data needs to travel internal network  | No network latency. Ultra-low latency and increased IOPS    |
| Backups                         | Flexible, can grow and move. Snapshots move between instances. | Rigid. No snapshots, no detaching, no resizing              |
| Cost                            | Pay for every gb provisioned separately from the ec2 instance  | Comes included on the specific instance type                |
