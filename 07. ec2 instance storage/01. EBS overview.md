# EBS (Elastic Block Store) Overview

- It's basically a virtual hard drive in the cloud that can be attached to an EC2 instance
- EC2 instances have temporary local storage called **Instance Store** (ephemeral storage)
  - if you stop or terminate an instance using instance store, all the data is lost
- EBS is permanent storage
  - EBS volume exists independently of the EC2 instance
  - Allows instances to persist data, even after their termination
  - If the EC2 instance crashes/is stopped, EB2 volume retains its data
- You can detach from one instance and attach it in another
- They can only be mounted to one instance at a time
- They are bound to a **specific availability zone**
- Think of them as a "network USB stick"

## EBS vs DB

EBS:

- operates at the OS level
- Doesn't know/care what the data means
- It just stores raw blocks of data

DB:

- operates at the application level
- takes complex data and organizes them into tables, indexes, or key-value pairs

## EBS Volume

- It uses the network to communicate with the instance, which adds latency
- It can be detached from an EC2 instance and attached to another
- It's locked to an AZ
  - To move volumes across AZ, you must take a snapshot

> **Similarly to EC2 instances, which is bound to an AZ, the EBS is also**

- Have a provisioned capacity (size in GBs, and IOPS [input/output per second])
  - you get billed by the provisioned capacity
  - you can increase the capacity of the drive over time
- You can't have two EC2 instances attached to the same EBS, however, you can have 2 EBS attached to the same EC2

## EBS - Delete on termination attribute

- When we create an EBS volume in the console, there is a column called "delete on termination".
  - Storage (volumens) / EBS Volumes / Delete on termination dropdown

- It controls the EBS behavior when the EC2 instance terminates
  - By default:
    - the root EBS is deleted (attribute enabled) when the EC2 instance is deleted
    - any other attached EBS volume isn't deleted (attribute disabled)
  - This however can be modified
    - use case: preserve root volume when instance is terminated
