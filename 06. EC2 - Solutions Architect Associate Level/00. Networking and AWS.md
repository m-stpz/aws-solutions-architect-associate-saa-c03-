# Networking and AWS

Six core layers:

- boundary definition
- traffic routine
- security
- edge delivery
- hybrid connectivity
- service-to-service access

## Virtual Private Cloud (VPC) & IP Addressing

- VPC is the logically isolated slice of AWS cloud
- CIDR Blocks: continues range of IP addresses for your VPC using CIDR notation
- Subnets: CIDR blocks are carved up into smaller subnets
  - the subnet is bound to a single AZ (availability zone)
  - public subnet: has a direct route to an Internet Gateway (IGW)
    - resources get public IP
  - private subnet: no direct internet route
    - standar practice for dbs, applications backends, and internal APIs

## Gateways and routing

- Traffic only moves where your route tables allow it to go
- Internet gateway (IGW): allows instances in public subnets to communicate bi-directionally with the internet
- NAT Gateway (Network address translation): placed in a public subnet to allow resources in a private subnet to reach out to the internet while blocking inbound traffic from initiating connections to them
- Route tables: explicity destination-to-target mapping to subnets
  - `Destination: 0.0.0/0 -> Target: igw-xxxxx`

## Defense

- AWS has two distinct layers of network firewalls. One stateful and the other stateless

| Concept      | Security groups                                  | Network ACLs (NACL)                                     |
| ------------ | ------------------------------------------------ | ------------------------------------------------------- |
| Scope        | Attaches to instances                            | Attaches to subnets                                     |
| Statefulness | Stateful: inbound/outbound equal                 | Stateless: outbound and inbound are allowed separately  |
| Rules        | Allow-only: denies everything else               | Allow AND Deny: evaluated explicitly                    |
| Usage        | Primary, fine-grained application-level firewall | Guardrail to block specific IP ranges/malicious subnets |

## Traffic distribution & Edge services

- Elastic load balancing (ELB): this is the load balancer
  - ALB (Application load balancer): operates at layer 7 (HTTP/HTTPS)
    - handles path-based routing
    - host headers
    - SSL termination
  - NLB (Network load balancer): operates at layer 4 (TCP/UPD)
    - ultra high-throughput
    - low latency
    - static IP Support
- Amazon route 53: DNS service capable of health-checks, latency-based routing, geo-location routing, failover management
- Amazon CloudFront: AWS's content delivery network (CDN)
  - caches content at edge locations worldwide to minimize latency
- API Gateway: Proxy front-door for backend microservices and lambda functions
  - authentication/authorization
  - rate limiting (throttling)
  - payload transformation
  - API versioning

```
[ Client Request ]
       │
       ▼
1. Route 53 (DNS) ──► Resolves "api.example.com" to the API Gateway or ALB endpoint.
       │
       ▼
2. API Gateway ─────► Handles Auth, Rate Limiting, & API routes.
       │
       ▼
3. Load Balancer ───► Distributes traffic across backend EC2 instances or ECS tasks.
```
