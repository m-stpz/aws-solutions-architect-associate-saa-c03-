# IPs: public, private, elastic

- Networking has two sorts of IPs: v4 and v6
  - IPv4: 1.123.12.321
  - IPv6: 199:4545:3:200:f8ff:fe21:g7cf

- IPv4: most commonly used
  - allows for 3.7 billion different addreses
  - format: `[0-255].[0-255].[0-255].[0-255]`

- IPv6: newer, most commonly used of IoT

## Public, Private, and Elastic

### Public

- machine can be identified in the internet
- must be unique across the WHOLE web (no two machines can have the same IP)
- can be geo-located

### Private

- private means that the machine isn't accessible publicly
- the machine is only identified over that private network
- must be unique across the PRIVATE network, not the whole web
  - two private networks can have the same IPs
- machines connect to the web using a NAT + internet gateway
- only specified range of IPs can be used as a private IP

> NAT Gateway (Network address translation): placed in a public subnet to allow resources in a private subnet to reach out to the internet while blocking inbound traffic from initiating connections to them

### Elastic

- When you stop -> start an EC2 instance, it changes its public IP
- If you need a fixed public IP, oyu need an Elastic IP
- Elastic IP is a public IPv4 you own as long as you don't delete it
- You can attach it to one instance at a time
- You can only have 5 elastic IP in your account (you can ask AWS to increase that)
- Overall, try to avoid using it
  - they often reflect poor architectural decisions
  - instead, use a random public IP and register a DNS name to it
  - or, use a load balance and then you have no need for a public IP

## IPs in EC2

- By default, the EC2 comes with:
  - a private IP for the internal AWS network
  - a public IP for the web

- When doing SSH into the EC2:
  - we can't use a private IP, since we're not in the same network
  - thus, we only can use a public IP

- If the machine starts/stops, the public IP changes
