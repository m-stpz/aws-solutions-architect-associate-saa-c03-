# Data Firehose

- Data Firehose, formerly known as Amazon Kinesis Data Firehouse, is a fully managed, serverless delivery service
- Designed for: capturing, transforming, and loading streaming data directly into:
  - storage
  - data lakes
  - analytics destinations
- Firehouse is completely hands-off, differently from Kinesis data streams, which require you to:
  - provision shards
  - manage consumer offsets
  - write custom code

- Firehose provides automatic scaling, serverless, pay for what you use
- Near real-time with buffering capability based on size/time

## How it works

1. Data lands in firehose

- either directly from producers [SDKs/agents] or automatically piped from a source
  - ex: KDS, CloudWatch logs, AWS IoT core

2. buffering: firehose doesn't write records one-by-one, instead if buffers records based on two conditions [buffer size/interval]
   - buffer size: ex, 5mb of data
   - buffer interval: ex, 300 seconds

3. in-flight transformation: before writing to destination, firehose can:
   - invoke aws lambda to clean, reformat or enrich invidual records
   - convert JSON payloads into other formats
   - perform dynamic partitioning

4. delivery: batched file is written to target destination
   - ex: s3, redshift, opensearch, 3rd-party monitoring

```
Producers ------------- record [up to 1mb] ---> Firehose ------- batch writes ----> Consumers
applications, KDS,                                 |                                aws destinations: s3, redshift, opensearch
client, CloudWatch, SDK,                    data transformation                     3rd-party: data dog, splunk, mongodb
Kinesis agent, AWS IoT                      lambda function                         custom destinations: http endpoint
```
