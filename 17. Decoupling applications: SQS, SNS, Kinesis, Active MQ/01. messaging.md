# Messaging

- When we start deploying multiple applications, they will need to communicate with one another
- Two patterns of application communication

1. Sync communication: application -> application
   - sync is easier to understand, debug, implement
   - however, it isn't scalable
     - it doesn't deal well with traffic spikes
     - if normally you need 10 units of compute, but then you suddenly need 1k

2. Async/event-based communication: application -> queue -> application
   - decoupling the application allows us to deal with increased load
   - SQS: queue model
   - SNS: pub/sub model
   - Kinesis: real-time streaming
