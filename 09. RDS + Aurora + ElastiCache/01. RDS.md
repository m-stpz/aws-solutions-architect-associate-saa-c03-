# RDS - Relational Database Service

- It's a relational db managed by AWS
  - managed db service that uses SQL as query language
- Create dbs in the cloud that are managed by AWS. RDS manages:
  - postgres, MySQL, MariaDB, Oracle, Microsoft SQL server, IBM DB2, Aurora (AWS Proprietary db)

## Why use RDS?

It's managed, thus AWS provides:

- Automated provisioning, OS patching
- Continuous backups and restore to specific timestamp (point in time restore)
- Monitoring dashboards
- Read replicas for improved read performance
- Multi AZ setup for DR (Disaster recovery)
- Maintenance windows for upgrades
- Scaling capabilities (vertical and horizontal)
- Storage backed by EBS

However, we can't SSH into the instances

## RDS - Storage auto scaling

- Increases storage in our RDS DB instance dynamically
- When RDS detects you're running out of free db storage, it scales automatically
- Avoid manually scaling your db storage
- You have a Maximum Storage Threshold
  - maximum limit for db storage
- Automatically modify storage if:
  - free storage is less than 10% of available space
  - Low-storage lasts at least 5 minutes
  - 6 hours have passed since last modifications
- Useful for applications with unpredictable workloads
- Supports all RDS db engines

## RDS Read Replicas vs Multi AZ

Read replicas are for performance (scaling reads), while multi-AZ is for disaster recovery

| Feature             | RDS Read replicas                                        | RDS Multi-AZ                                                                    |
| ------------------- | -------------------------------------------------------- | ------------------------------------------------------------------------------- |
| Purpose             | Read scalability and performance                         | High availability and fault tolerance                                           |
| Replication mode    | Async (eventually consistent)                            | Sync (strong consistency)                                                       |
| Behavior            | Active for reads (applications connect directly to them) | Passive standby (cannot be read from or written to)                             |
| Failover behavior   | Manual (must promote replica to standalone db)           | Automatic (RDS switches DNS automatically in 60-120s)                           |
| Connection endpoint | Has its own separate DNS endpoint for read traffic       | Single DNS endpoint (AWS switches IP underlying IP during failover)             |
| Geographic scope    | Same AZ, Cross-AZ, or Cross-Region                       | Same region only (across different AZs)                                         |
| Backups impact      | Backups are separate (disabled by default on replicas)   | Automated daily snapshots are taken from the standby (no I/O freeze on primary) |

When to use...

- Read replicas
  - production db is read-heavy and the primary CPU is spiking
  - running heavy analytical, reporting or BI queries and we want to avoid locking tables/slowing down db
  - cross region replicas to lower read latency for global users

- Multi-AZ
  - need zero downtime failover
  - automated db OS patching and maintenance without taking application down
  - automated backups without taking I/O performance on prod db

### RDS Read Replicas

- Up to 15 read replicas
- They can be within AZ, Cross AZ or Cross Region
- Replication is async -> reads are eventually consistent
- Replicas can be promoted to their own db
