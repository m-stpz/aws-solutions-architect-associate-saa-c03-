# S3 Performance

## Baseline performance

- S3 is by default incredibly scalable
- It automatically scales to high request rates
  - latency 100-200ms
- Application can achieve `_____` requests per second per prefix in a bucket
  - 3,5k PUT/COPY/POST/DELETE [mutations]
  - 5,5k GET/HEAD [query]
- No limits to the number of prefixes in a bucket
- What is a prefix?
  - the path between the bucket/ ... to the / file

```
      | -- prefix ---|
bucket/folder/1/sub1/file
```

| object path              | prefix         |
| ------------------------ | -------------- |
| bucket/folder1/sub1/file | /folder1/sub1/ |
| bucket/folder1/sub2/file | /folder1/sub2/ |
| bucket/1/file            | /1/            |
| bucket/2/files           | /2/            |

- If we spread reads across all prefixes evenly, we can get 22k requests per second for GET/HEAD

## Performance

### 1. Multi-part upload

- recommended for files > 100MB,
- must use for files > 5gb
- can help parallelize uploads

```
        parallel uploads / chunk
         / part 1  \
big file -- part 2 -- amazon s3
         \ part 3 /
                s3 assembles it
```

- Basically, it breaks the file into smaller chunks
  - these chunks are uploaded concurrently or even out of order over the network
  - then s3 assembles it into a coherent object

Under the hood:

1. initiation
2. uploading parts
3. completion
