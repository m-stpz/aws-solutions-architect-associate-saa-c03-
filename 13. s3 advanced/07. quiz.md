# S3 Advanced Quiz

1. How can you be notified when there's an object uploaded to your S3 bucket?

- S3 Event notifications

2. You have an S3 bucket that has S3 Versioning enabled. This S3 bucket has a lot of objects, and you would like to remove old object versions to reduce costs. What's the best approach to automate the deletion of these old object versions?

- S3 lifecycle rules - expiration actions
  - why?
    - s3 lifecycle rules fall into two categories
      - 1. expiration actions: used to DELETE objects or versions permanently
      - 2. transition actions: used to MOVE objects between storage classes
        - alive, only changed the storage tier

3. How can you automate the transition of S3 objects between their different tiers?

- S3 lifecycle rules

4. While you're uploading large files to an S3 bucket using Multi-part Upload, there are a lot of unfinished parts stored in the S3 bucket due to network issues. You are not using these unfinished parts and they cost you money. What is the best approach to remove these unfinished parts?

- Use s3 lifecycle policy to automate old/unfinished parts deletion

5. You are looking to get recommendations for S3 Lifecycle Rules. How can you analyze the optimal number of days to move objects between different storage tiers?

- S3 analytics
  - why?
    - analytics:
      - actively monitors and analyzes object access patterns across buckets
    - inventory:
      - static control of your objects and their metadata
      - doesn't track frequency, nor does it offer lifecycle recommendations

6. You are looking to build an index of your files in S3, using Amazon RDS PostgreSQL. To build this index, it is necessary to read the first 250 bytes of each object in S3, which contains some metadata about the content of the file itself. There are over 100,000 files in your S3 bucket, amounting to 50 TB of data. How can you build this index efficiently?

- Create a an application that will traverse the the s3 bucket, issue a byte range fetch for the first 250 bytes, and store that info in RDS
  - why?
    - byte range fetch allows us to request the exact initial slice of an object, without downloading the rest
      - downloading the entire file: 50tb of network transfer and disk I/O
      - using s3 byte range fetch: 100k x 250 bytes = 25MB total data transferred!
  - why not...
    - use RDS import feature to load the data from s3 to postgresql?
      - this would load the 50tb into the db
    - create an application that will traverse the s3 bucket, read the files one by one, and extract the first 250 bytes?
      - means downloading every file in its entirity, then slicing the first 250 bytes
      - still moves 50tb of data across the network
    - create an application that will traverse the s3 bucket, use athena to get the first 250 bytes?
      - athena is an interactive SQL engine for structured/semi-structured file formats
      - it can't parse raw binary files

Whenever in the scenario, you have `____`, the correct architectural mechanism is **S3 byte range fetch**

- reading file headers, initial metadata, specific slices or large files in S3
- speeding up downloads by requesting multiple chunks concurrently
