# S3 Events notifications

- Object:
  - created
  - removed
  - restored
- Replication
- Object name filtering possible
- Use case: a post-processing job after something happens on s3
  - ex: generate thumbnails of images uploaded to s3
- Can create as many "s3 events" as desired
  - they can feed other services

```
events              / SNS
------- aws s3 ------ SQS
                    \ Lambda functions
```

- The event notifications typically deliver events in seconds but can sometimes take a minute or longer

## IAM Permission

- So that our bucket can send messages to SNS/SQS/Lambda, it needs a <element> resource access policy

## EventBridge

```
events      all events              rules
-----  aws s3 ------> EventBridge -------> over 18 aws services as destinations
        bucket
```

- Besides being a centralizing hub, Event bridge offers:
  - advanced filtering options with JSON rules (metadata, object size, name...)
  - multiple destinations, ex: step functions, kinesis streams / firehose...
  - capabilities
    - archive
    - replay events
    - reliable delivery

## Hands on

- Amazon S3 / Buckets / <bucket-name>
- click on `properties`
  - event notifications
  - create event notification OR enable amazon eventbridge
    - create event notification
      - select event
      - destination: lambda, SNS, SQS
        - then, remember that your service needs to accept requests from the s3 bucket [resource access policy]
