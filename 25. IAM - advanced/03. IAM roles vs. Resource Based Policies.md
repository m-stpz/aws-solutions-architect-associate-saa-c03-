# IAM Roles vs. Resource-based policies

- Cross account:
  - attaching a resource-based policy to a resource [example: s3 bucket policy]
    - principal doesn't have to give up his permissions
  - OR using a role as a proxy
    - role: you give up your original permissions and take ONLY the permissions assigned to the role

```
user account A -----> Role Account B -----> S3
user account A -----> S3 bucket policy ---> S3
```

## IAM permission boundaries

- Safety guardrail that sets maximum permissions an IAM user/role can have
- Doesn't grant permission, only restricts what permissions can be granted

- IAM policy = cash in your wallet
- Permission boundary = credit card spending limit

## Policy evaluation logic

- AWS evaluates every request using a strict, top-to-bottom decision flow
  - golden rule: default deny
    - unless a request is explictly allowed and NEVER explicitly denied, it's rejected

Evaluation flow

1. Check for explicit deny
   - AWS scans all applicable policies [identity, resource, SCPs, boundaries, session policies]

2. Check AWS organizations SCPs [service control policy]
   - if the account belongs to an AWS org, the service control policy [SCP] must explicitly allow the action

3. Check resource-based policies

4. Check IAM permissions boundary
   - if permission boundary is attached to the user or role, it must explicitly allow the action

5. Check session policies

6. Check identity-based policies

```
                      [ API Request ]
                             │
                             ▼
               ┌───────────────────────────┐
               │ 1. Explicit DENY anywhere? │ ──( YES )──► [ DENY ]
               └───────────────────────────┘
                             │ (NO)
                             ▼
               ┌───────────────────────────┐
               │ 2. Organizations SCP      │ ──( NO )───► [ DENY ]
               │    explicitly ALLOWS?     │
               └───────────────────────────┘
                             │ (YES / No Org)
                             ▼
               ┌───────────────────────────┐
               │ 3. Resource-Based Policy  │ ──( YES )──► [ ALLOW ] *
               │    explicitly ALLOWS?     │   *(Same-account only)
               └───────────────────────────┘
                             │ (NO / Cross-account)
                             ▼
               ┌───────────────────────────┐
               │ 4. Permissions Boundary   │ ──( NO )───► [ DENY ]
               │    explicitly ALLOWS?     │
               └───────────────────────────┘
                             │ (YES / None)
                             ▼
               ┌───────────────────────────┐
               │ 5. Session Policy         │ ──( NO )───► [ DENY ]
               │    explicitly ALLOWS?     │
               └───────────────────────────┘
                             │ (YES / None)
                             ▼
               ┌───────────────────────────┐
               │ 6. Identity-Based Policy  │ ──( YES )──► [ ALLOW ]
               │    explicitly ALLOWS?     │
               └───────────────────────────┘
                             │ (NO)
                             ▼
                   [ DENY (Implicit) ]
```
