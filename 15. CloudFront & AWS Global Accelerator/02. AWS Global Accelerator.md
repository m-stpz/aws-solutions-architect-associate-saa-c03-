# AWS Global Accelerator

- Let's say you have a deployed application and have global users who want to access it directly
- They go over the public internet, which can add latency and many hops
- To solve this, we can go through AWS network to minimize latency

```
             | --- [3 hops] ---> Australia
| public ALB | --- [5 hops] ---> Europe
             | --- [7 hops] ---> USA
```

## Unicast IP vs. Anycast IP

- Unicast IP: one server holds one IP address
  - client
    |---- server 1 [12.34.56.78]
    |---- server 2 [98.76.54.32]

- Anycast IP: N servers hold the SAME IP address and the client is routed to the NEAREST one
  - client
    |---- server 1 [12.34.56.78]
    |---- server 2 [12.34.56.78] -> client routed here, the closest one

## AWS Global Accelerator concepts

- Uses the concept of Anycast IP + AWS internal network to route to your application
- 2 Anycast IP are created for your application
- The Anycast IP sends traffic directly to edge locations
- The edge locations send the traffic to your application

```
             | --- [edge location] --[through AWS Private network]--> Australia
| public ALB | --- [edge location] --[through AWS Private network]--> Europe
             | --- [edge location] --[through AWS Private network]--> USA
```

- Works with Elastic IP, EC2 instances, ALB, NLB
- Consistent performance
  - intelligent routing to the lowest latency and fast regional failover
  - no issue with client cache, because the IP doesn't change
  - internal AWS network
- Health checks
  - global accelerator performs a health check on the applications
  - helps make the application global
    - failover less than 1 minute for unhealthy
  - great for DR
- Security
  - only 2 IPs to be whitelisted
  - DDoS protection, thanks to AWS shield

### CloudFront vs. Global Accelerator

- They both:
  - increase performance
  - reduce latency
  - use AWS global network infra
  - integrate with AWS Shield for DDoS protection

However, they serve different purposes

- Use CloudFront for:
  - serving web apps, static assets, and for content that can be cached at the edge
  - improving performance for cacheable content [images, videos, fonts, JS]
  - serving content at the edge, once cached, it doesn't need, during the TTL, to hit the server
- Use Global accelerator for:
  - serving non-HTTP/HTTPS traffic
  - allowing clients to connect to fixed static IP addresses
  - bypassing public internet congestion for general TCP/UPD traffic by using AWS private fiber

| Feature       | CloudFront                                                                                          | Global Accelerator                                                  |
| ------------- | --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| OSI Layer     | Layer 7 [application layer]                                                                         | Layer 4 [transport layer]                                           |
|               | Optimized for HTTP, HTTPS, and Websockets                                                           | Optimized for any TCP and UDP traffic [including gaming, IoT, etc.] |
| Caching       | Yes                                                                                                 | No                                                                  |
|               | Caches static/dynamic content at edge locations, serving content without hitting the origin servers | Acts as a network proxy, routing packes through AWS network         |
| IP addressing | Uses DNS names [CNAMEs] mapped to edge distributions                                                | Provides two static Anycast IP addresses                            |
| Routing       | Based on URL path, request headers, cookies                                                         | Based on optimal network performance                                |
