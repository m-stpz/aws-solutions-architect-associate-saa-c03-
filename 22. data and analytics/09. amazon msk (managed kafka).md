# Amazon MSK [Managed Streaming for Apache Kakfa]

- Alternative for Amazon Kinesis
  - build and run prod applications that use Kafka to process streaming data
  - without having to manage the underlying infra
  - MSK vs. Kinesis data streams?
    - MSK:
      - if you already are in the kafka ecosystem
      - need complex topic/partition archi
      - require custom stream processing semantics
    - Kinesis
      - purely serverless
      - AWS-native data streaming service
      - minimal config overhead

- Handles the heavy lifting of `____` kafka clusters
  - provisioning
  - configuring
  - scaling
  - patching
- Fully managed Kafka on AWS
  - allow you to create, update, delete clusters
  - MSK creates and manages Kafka brokers nodes and zookepers nodes
  - deploy the MSK cluster in your VPC, multi-AZ [up to 3 for HA]
  - automatic recovery from common apache kafka failures
  - data is stored on EBS volumes as long as you want
- MSK serverless
  - run kafka on MSK without managing capacity

Trigger: Migrate an existing open-source kakfa workload to AWS with full API compatibility and zero infra management -> Amazon MSK

- always deploy MSK clusters across at least 3 AZs

## Kinesis Data Streams vs. Amazon MSK

| Feature           | Kinesis Data Streams                                                              | MSK                                                                               |
| ----------------- | --------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| Underlying tech   | AWS-proprietary streaming                                                         | 100% open-source kafka                                                            |
| Core scaling unit | shards, each shard handles 1 mb/s write and 2mb/s read                            | partitions and brokers [distributed across kafka topics and clusters]             |
| Data retenttion   | default 24h, extendable to 365 days                                               | bounded by disk storage, can be stored for years                                  |
| Cost profile      | cost-effective at low/spiky throughput                                            | fixed infra/cluster price, but highly efficient for massive sustained throughput  |
| use case          | AWS native solution, low-ops, serverless streaming integration with AWS ecosystem | migrate existing kafka workloads to AWS with zero code changes and full API match |
