# OpenSearch/ElasticSearch

- OpenSearch is successor to ElasticSearch
- In DynamoDB, queries only exist by primary key or indexes, however, with OpenSearch we can search any field, even partially matches
- **It's common to use OpenSearch as a complement to another db**
- Two modes:
  - managed cluster
  - serverless cluster
- Doesn't natively support SQL -> it must be enabled via a plugin
- Receives input from:
  - Kinesis data firehose
  - AWS IoT
  - CloudWatch logs
- Security through:
  - Cognito and IAM
  - KMS encryption
  - TLS
- Comes with OpenSearch dashboards [visualization]

## Patterns with OpenSearch

### DynamoDB

- While NoSQL dbs are great at lightining-fast key-value lookups, they are bad at complex, open-ended search queries
  - ex: full-text search, regex filtering, fuzzy matching, multi-field aggregations

```
CRUD
------> DynamoDB Table ---> DynamoDB stream ----> Lambda ----> OpenSearch
              |                                                   |
        api to retrieve items -----[compute]----- api to search items
```

- Read/Query path
  - when a user interacts with the application, the backend decides where to route the read request based on the type of query
    - API to retrieve items [exact lookup]
      - if the app needs specific record by its pk, it queries dynamodb
    - API to search items [complext/text search]
      - if the app needs more complex queries [full-text search, filtering, sorting, autocomplete], it queries OpenSearch

```
               ┌───────────────────────────────┐
               │    Client Request Received    │
               └──────────────┬────────────────┘
                              │
            ┌─────────────────┴─────────────────┐
            │ Is it a Lookup by ID              │ Is it a Complex Search / Filter / Text Query?
            │ or a Full-Text Search?            │
            ▼                                   ▼
┌───────────────────────┐           ┌───────────────────────┐
│     DynamoDB Table    │           │    Amazon OpenSearch  │
│ (Fast Key-Value Read) │           │  (Full-Text / Search) │
└───────────────────────┘           └───────────────────────┘
```

### CloudWatch Logs

```
                                                            real-time
CloudWatch logs --> Subscription filter ----> Lambda function -------> OpenSearch
                                             [managed by AWS]

                                                                 near real-time
CloudWatch logs --> Subscription filter ----> Kinesis Data Firehose -------> OpenSearch
```

- Lambda-based pipeline [real-time]
  - highly flexible
  - however, under massive log floods, lambda concurrency limits and invocation costs must be checked

- Firehose-based pipeline [near real-time]
  - zero custom code to maintain
  - less granular transformation flexibility
  - allows massive scale, durability, and cost-effectiveness
