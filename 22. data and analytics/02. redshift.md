# RedShift - Data Warehouse

- Redshit is based on Postgres, but it's not used for OLTP [online transaction processing], but for OLAP [online analytical processing]

> For more info, see 00.intro/16.OLTP vs. OLAP

- OLAP: online analytical processing
  - analytics and data warehousing

- 10x better performance than other data warehouses, scales to PBs of data
- Columnar storage of data, instead of row-based, & parallel query engine
- Two modes:
  - provisioned cluster
  - serverless cluster
- Has a SQL interface for performing queries
- BI tools such as Quicksight or Tableau integrate with it
- vs. Athena:
  - faster queries, joins, aggregations thanks to indexes

## Redshift vs Athena

- Both Redshift and Athena are built for OLAP

- When to use Athena: great for quick, exploratory checks
  - fastest path to query data s3 data with zero infra management
  - performing ad-hoc [on the fly, spontaneous, instead of routine] data exploration, log analysis, quick SQL queries over log files, JSON payloads, or data lakes
  - queries are irregular, infrequent

- When to use Redshift: great for heavy, complex analytical queries and deep BI usage
  - building central enterprise data warehouse combining data from multiple production databases, CRM systems, and SaaS apps
  - power users and BI tools running massive, concurrent reporting
  - advanced data warehousing features

## Redshift Cluster

- Leader node: query planning, results aggregation
- Compute node: performing queries, sned results to the leader
- Provisioned mode
  - choose instance types in advance
  - can reserve instances for cost saving

```
Query [SELECT COUNT *, ... FROM <TABLE> GROUP BY...]
 |
------- Redshift cluster
 Leader node
    |---- [compute nodes]
```

## Snapshots & DR

- Redshift has multi-az mode for some clusters
- Snapshots are point-in-time backups of a cluster, stored internally in s3
- Snapshots are incremetnal, only what has changed is saved
- You can restore snapshot into a new cluster
- Automated:
  - every 8h
  - every 5gb
  - schedule
  - set retention
- Manual: snapshot is retained until you delete it
- It's possible to copy snapshots [automated/manual] of a cluster to another AWS region

```
us-east-1
redshift cluster ---> cluster snapshot
[original]                  |
                            | automated / manual copy
                            |
eu-west-1                   |
redshift cluster <---- copied snapshot
[new]
```

## Loading data into Redshift

- Large inserts are much better

1. Amazon kinesis data firehose
   - Kinesis data firehose -> Redshift cluster [through s3 copy]

2. S3 using COPY command
   - s3 bucket -> Redshift cluster
     - internet: without VPC routing
     - through VPC: with VPC routing

```bash
copy customer
from "<bucket>"
iam_role "arn:aws:iam::..."
```

3. EC2 instance
   - JDBC driver
   - EC2 instance -> redshift
   - better to write data in batches

## Redshift Spectrum

- Query data that's already in s3 without loading it
- Must have a Redshift cluster available to start the query
- Query is submitted to thousands of redshift spectrum nodes
