# Elastic Load Balancer

- Load balancers are servers that forward traffic to multiple servers (e.g. EC2 instances) downstream

```
user1 -----> |               | ----> ec2 instance 1
user2 -----> | load balancer | ----> ec2 instance 2
user3 -----> |               | ----> ec2 instance 3
```

## Why to use a load balancer?

- Spread load across multiple downstream instances
- Expose a single point of access (DNS) to your application
- Easier to handle failures on downstream instances: re-route traffic when instance is down
- Health check on the instances
- SSL termination
- Separate public traffic from private one

## Why to use AWS managed Elastic Load Balancer (ELB)?

- AWS...
  - guarantees it'll be working
  - takes care of upgrades, maintenance, high availability
  - provides config knobs

- Costs less to setup your own load balancer, but it'll demand more effort on your side
- Integrated with many AWS services
  - EC2, EC2 auto scaling groups, Amazon ECS
  - AWS Certificate manager (ACM), CloudWatch
  - Route 53, AWS WAF, AWS Global accelerator

## Health checks

- Load balancer verifies if the instance is running
- Health checks are crucial for load balancers
  - they allow the load balancer to know if the instances it forwards traffic to are available to reply to requests
  - it's done on a port and a route (/health is common)
  - if response is not 200 (OK), then the instance is unhealthy

```
elastic load balancer ----> health checks ----> ec2 instance
                        protocol: http
                        port: 3006
                        endpoint: /health
```

## Types of load balancers on AWS

`_____` load balancer

- Classic [CLB]: v1, old generation
  - HTTP, HTTPS, TCP, SSL
  - labeled as deprecated by aws
- Application [ALB]: v2, new gen
  - HTTP, HTTPS, WebSocket
- Network [NLB]: v2, new gen
  - TCP, TLS, UDP
- Gateway [GWLB]
  - Operates at layer 3 (network layer) - IP Protocol

- Recommended to use newer lb gen
- Some LB can be setup as internal/private or external/public

## Load balancer security groups

```
    HTTP/HTTPS            HTTP Restricted
    from anywhere         to load balancer
users <---> load balancer <---> EC2
```

- Load balancer security group:
  - allows HTP/HTTPS on the given port (HTTP: 80, HTTPS: 443) from anywhere (0.0.0.0/0)

- EC2 Instance:
  - allows HTTP from the source that is the load balancer security group, instead of an IP range
