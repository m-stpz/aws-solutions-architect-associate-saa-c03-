# Application Load Balancer (ALB)

- ALB is layer 7 (HTTP)
- Load balancing to multiple
  - ... HTTP applications across machines (target groups)
  - ... applications on the same machine (ex: containers)
- Support for HTTP/2 and WebSocket
- Support redirects (ex: from HTTP to HTTPS)
- Routing tables to different target groups:
  - routing based on:
    - path in URL: example.com/users | example.com/posts
    - hostname in URL: one.example.com | other.example.com
    - query string, headers: example.com/users?id=123&order=false

- ALB are great for microservices and container-based application
- Has port mapping to redirect to dynamic port in ECS

## HTTP based traffic

- The load balancer knows how to route to the given target group based on the URL

```
client ---> route /user ---> |          | --> http --> target group for users application
                             | load     |              ec2 instance1 | ec2 instance two
                             | balancer | --> http --> target group for search application
client ---> route /search -> |          |              ec2 instance1 | ec2 instance two
```

### Target groups

They can setup on:

- EC2 instances (can be managed by an auto scaling group) - HTTP
- ECS tasks (managed by ECS itself) - HTTP
- Lambda functions: HTTP request is translated into JSON event
- IP Addresses: must be private IPS

- ALB can route to multiple target groups
- Health checks are at the target group level

## ALB Good to know

- Fixed hostname (xxx.region.elb.amazonaws.com)
- The application servers don't see the IP of the client direclty
  - The true IP of the client is inserted in the header `X-Forwarded-For`
  - We can also get Port (`X-Forwarded-Port`) and proto (`X-Forwarded-Proto`)

## Hands on

- Launch the EC2 instances, in case they aren't running
- Then on EC2 instances, go to Load balancing / load balancers
  - Scheme: internet-facing or internal
  - IP address type: IPv4
  - Select the different AZs that the load balancer will attend
  - Select the VPC
  - Assign a security group
    - it should allow inbound HTTP (:80) from anywhere `0.0.0.0/0`
  - Listeners and routing
    - route traffic from HTTP on port 80 to a target group
      - if not created yet, create the target group

### Limiting the EC2 instances to be accessible only through the ALB

- Network and security / Security groups
- Select the group of the EC2 instances and modify:
  - inbound rules: we only accept inbound traffic coming from the ALB
    - type: http
    - source: the security group of the load balancer

### Adding specific rules to ALB

- EC2 / Load balancers / <ALB-name>
- Then add rule
  - we can specify it as we want:
    - select by: host header, path, HTTP request method, source IP, HTTP header, query string
