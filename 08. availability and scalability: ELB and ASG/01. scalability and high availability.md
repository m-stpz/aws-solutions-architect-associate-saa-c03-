# Scalability and high availability

- Scalability: system can handle greater loads
  - two types: vertical and horizontal

## Vertical scalability

- Increase the size/power of the instance
- e.g: `t2.micro` -> `t2.large`
- Common for non distributed systems, such as a db
- RDS, ElastiCache are services that can scale vertically
- There's a limit of how much the instance can be scaled vertically (hardware limit)

## Horizontal scalability

- Increase the number of instances
  - auto scaling group
  - load balancer
- Implies distributed systems
- The cloud makes it easier to scale horizontally

## High availability

- Usually goes hand in hand with horizontal scaling
- High availability means running the system in at least 2 data centers (system running >= 2 AZs)
  - this way we survive a data center loss
- High availability can be:
  - passive: RDS multi AZ for example
  - active: horizontal scaling
