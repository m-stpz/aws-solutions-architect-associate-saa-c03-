# IAM

- IAM: Identity and Access Management
- Global service
- Users are people within your organization, and can be grouped

Groups can container users, but not other groups

- users don't have to be part of a group and they could also belong to multiple groups

- Group:
  - develepers
  - operations

## Permissions

- Users and groups can be assigned policies [JSON documents]
  - this JSON document says who has acess to what
  - the policies define the user's permissions
- in AWS, we use the least privilege principle
  - don't give more permissions than a user need
  - permissions aren't granted by default, you need to select to grant them
- It's simpler to manage permissions for a batch of users this way

> It's a best practice not to perform operations on AWS as the root user

- You can have a multi-session support. This way, you don't need to have two browsers open or an anonymous tab

## IAM Policies Inheritance

- When creating policies to a group, users will inherit that policy
- We can also create policies for a user specifically [called inline policies]

### Policies Structure

A policy has:

- version: policy language version
- id?: id of the policy
- statement!: one or more individual statements

A statement has:

- Sid
- Effect
- Principal
- Action
- Resource

```json
{
  "Version": "2026-10-07",
  "Id": "S3-Account-Permissions",
  "Statement": [
    {
      "Sid": "1",
      "Effect": "Allow",
      "Principal": {
        "AWS": []
      },
      "Action": [],
      "Resource": []
    }
  ]
}
```
