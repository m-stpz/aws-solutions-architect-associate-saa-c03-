# IAM

- IAM: Identity and Access Management
- Global service
- Users are people within your organization, and can be grouped

Groups can container users, but not other groups

- users don't have to be part of a group and they could also belong to multiple groups

- Group:
  - develepers
  - operations

## Permissions

- Users and groups can be assigned policies [JSON documents]
  - this JSON document says who has acess to what
  - the policies define the user's permissions
- in AWS, we use the least privilege principle
  - don't give more permissions than a user need
  - permissions aren't granted by default, you need to select to grant them
- It's simpler to manage permissions for a batch of users this way

> It's a best practice not to perform operations on AWS as the root user

- You can have a multi-session support. This way, you don't need to have two browsers open or an anonymous tab

## IAM Policies Inheritance

- When creating policies to a group, users will inherit that policy
- We can also create policies for a user specifically [called inline policies]

### Policies Structure

A policy has:

- version: policy language version
- id?: id of the policy
- statement!: one or more individual statements

A statement has:

- Sid?: statement identifier
- Effect: whether it allows/denies
- Principal: account/user/role to which this policy is applied to
- Action: list of actions this policy allows/denies
- Resource: list of resources to which the actions are applied to
- Condition?: conditions for when this policy is in effect

```json
{
  "Version": "2026-10-07",
  "Id": "S3-Account-Permissions",
  "Statement": [
    {
      "Sid": "1",
      "Effect": "Allow", // allow/deny
      "Principal": {
        // whom is this policy applied to?
        "AWS": []
      },
      "Action": [], // list of actions it allows/denies
      "Resource": [] // to what the actions are applied to?
    }
  ]
}
```

- User can inherit the policies from the groups it belongs to, as well as what is given to him individually
- We can use the built-in policies by amazon, but we can also create our own
- The policy has a JSON format, so we can see the statement that is being implemented and its:
  - effect
  - action
  - resource

### IAM - Password policy

1. We can define the password policy:

- Strong passwords
  - Set a minimum password length
  - Require specific character types [upper,lower, numbers, non-alphanumberic]
- Allow users to change their passwords
- Require users to change their password after some time
- Prevent password re-use

2. MFA [Multi Factor Authentication]

- Root account and IAM users should need MFA authentication
- MFA: password you know + device you own
  - even if the password is compromised, the account remains secure

- Types of MFA options
  - Virtual MFA device [Google Auth, Authy]
  - Physical MFA device
    - 2nd factor authenticator security key
    - Hardware key fob MFA device
