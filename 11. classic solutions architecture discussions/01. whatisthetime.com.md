# WhatIsTheTime

- Allows people to know what time it is
- Don't need a db, servers know the time
- Start small, accept downtime and go from there
- Then, no downtime, we should scale vertically and horizontally

## V1

```
                                    | elastic IP address
user --- what time is it? ---> ec2 instance
     <-- returns the time ---- [t2.micro]
```

- Why elastic IP address?
  - Elastic IP (EIP) is a static, public ipv4 address allocated to your AWS account
  - The IP is static, so what is elastic isn't the IP itself, but the fact that it can be attached/detached
  - You can programatically attach/detach/remap it between EC2 instances

  - remember, if the EC2 instance is stopped, AWS releases its IP back into the shared pool
    - then, it assigns a new one once it's back

  - the EIP stays assigned to your account, when the EC2 crashes/goes down, spin a new EC2 instance
    - then remap the EIP to the new instance
    - clients continue hitting the same IP as before

## V2 - Scale vertically

- We increased the ec2 instance size/power [scale vertically]

```
                                                 | elastic IP address
hundreds of users --- what time is it? ---> ec2 instance
                  <-- returns the time ---- [m5.large]
                                                  | downtime while upgrading to m5
```

## V3 - Scale horizontally

- v3.1 We could when adding more servers, keep the Elastic IP, but this isn't good. Why?
  - because the users would need to know the specific IP of the given instance. That's bad

- v3.2 We eliminate the Elastic IP and instead we use route 53 and add the multiple IPS there. Better, but still bad. Why?
  - in this case, the Route 53 DNS record would be a `A` record for the IPs
  - what if we need to bring one instance down or it crashes?
    - the route 53 registry would still have the outdated IP

- v3.3 So, we've seen that route 53 isn't enough. What should we do now? Implement a public load balancer with private instances
  - in this case, the Route 53 DNS record would be an `alias`, since the LB IP can change all the time
  - only the LB knows about the instances. It's the only interface clients need to worry about
  - then, the instances can go down and the ELB deals with that
    - users don't perceive any instance was down

```
                                                   AZ 1                AZ 1

DNS Query                                                     ----------- m5
for api.whatisthetime.com <------ users ---------> ELB +      ----------- m5
Alias Record                                      Health checks -------- m5

                                                                    private ec2 instances
```
