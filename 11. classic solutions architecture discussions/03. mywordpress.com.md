# MyWordPress

- Stateful application
- We want to be able to store images

## Solution 1: EC2 Instance + EBS

- We can have our image be uploaded to EBS through our EC2 instance
  - problem:
    - we have only once instance. We get back to the beginning where we lack availability, DR, etc
    - EBS works well for a single instance, if you have multiple instances, then it doesn't scale well

```
 ----------- route 53
 |
user --- send image ------ ELB-----------  AZ1 [ec2 instance m5] + EBS
                        multi AZ           AZ2 [ec2 instance m5] + EBS
```

- If we tried adding more ec2 instances, the image might have been upload to one EBS and not be available in another

## Solution 2: EC2 Instance + EFS

- We can solve the problem above by instead of using an EBS, we use an EFS
  - EFS [Elastic File System] creates ENI [Elastic Network Interface]
  - The ENI is created in each AZ and can be used by all EC2 instances within that given AZ

```
 ----------- route 53
 |
user --- send image ------ ELB-----------  AZ1 [ec2 instance m5] ENI ---- EFS
                        multi AZ           AZ2 [ec2 instance m5] ENI ------|
```

### Why EFS and not S3 in this scenario?

- If the question is about making an existing legacy applicartion or CMS multi-az without re-architecting the code, EFS is almost always the correct answer
- However, in modern web architecture, S3 is vastly superior to EFS for static assets
  - S3 standard storage is much cheaper than EFS per GB ($0.023/gb vs. $0.30/gb)
  - Direct browser delivery: doesn't need to pass through the EC2 instance
