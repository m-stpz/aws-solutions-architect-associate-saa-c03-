# EC2 Instance Purchasing options

- On-demand instances: short workload, predictable pricing, pay by second
- Reserved: 1 and 3 yeras
- Saving plans
- Spot instances
- Dedicated host
- Dedicated instances
- Capacity reservations

## EC2 On Demand

- Pay for what you use
  - linux/windows: billing per second, after the first minute
  - all other os: per hour
- Highest cost, but no upfront payment
- No long-term commitmment
- Better for **short-term** and **un-interrupted workloads**, where you can't predict how the application will behave

## EC2 Reserve instances

- Good for steady-state usage applications
- Up to 72% discount compared to on-demand
- Reserve a specific instance attributes (instance type, region, tenancy, os)
- Reserve it for a period: 1 year (+discount) or 3 years (+++discount)
- Payment options: no/partial/all upfront

## EC2 Savings PLans

- Get a discount on long-term usage
- Commit to a certain type of usage ($10/h for 1/3 years)
- Usage beyond this is billed at on-demand price

## EC2 Spot instances

- Can get a discount of up to 90% to on-demand
- However, you can "lose" them at any point in time, if your max price is less than the current spot price
  - it's like audictioning for ec2 instances
- The most cost-efficient instances in AWS
- Useful for workloads that are resilient to failure
  - batch jobs
  - data analysis
  - image processing
  - any distributed workloads
  - workloads with a flexible start/end time

- Not suitable for critical jobs or dbs

- Define max_spot_price and get the instance while current_spot_price < max

https://aws.amazon.com/ec2/spot/pricing/
https://calculator.aws/#/ -> pricing calculator

### How to terminate spot instances

- You can only cancel spot instance requests that are open, active, or disabled
- Cancelling a spot request doesn't terminate instances
- You must first cancel a spot request, and then terminate the associated spot instances

### Spot Fleets

- Spot fleets = set of spot instances + on-demand instances (optional)
- Tries to meet the target capacity with price constraints
  - define possible launch pools: instance types, OS, availability zone
  - can have multiple launch pools, so fleet can choose
  - spot fleet stops launching instances when reaching capacity or max cost
- Strategies to allocate spot instances
  - lowestPrice: from the pool with the lowest price (cost optimization, short workload)
  - diversified: distributed across all pools (great for availability, long workloads)
  - capacityOptimized: pool with the optimal capacity for the number of instances
  - priceCapacityOptimized (recommended): pools with highest capacity available, then select the pool with the lowest price (best choice for most workloads)

> Spot fleets allows us to automatically request spot instances with the lowest price

- To open it, go to EC2/Instances/Spot Requests
  - there you can select per instance and see the pricing history
  - usually the price is more than 50% below the on-demand one
  - this will request a spot fleet
    - to request a spot instance, go to EC2/Instance/Request, as you'd be a normal instance
    - there on advanced details, you'll have the option `spot instances`

## EC2 Dedicated host

- A physical server with EC2 instance capacity fully dedicated to your use
- Good for compliance requirements and usage of your existing server-bound software licenses
- Purchasing options: on-demand and reserved
- The most expensive option
- Useful for:
  - softwares with complicated licensing model
  - companies with strong regulatory/compliance needs

## EC2 Dedicated instance

- Instance runs on hardware that's dedicated to your
- May sahre hardware with other instances in same account
- No control over instance placement
