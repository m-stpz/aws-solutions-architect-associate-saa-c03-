# CNAME vs. Alias

- AWS resources (load balancer, cloudfront, ...) expose an AWS hostname
- CNAME:
  - points a hostname to any other hostname (app.mydomain.com -> blabla.anything.com)
  - only for NON-ROOT domain
    - ❌ mydomain.com
    - ✅ something.mydomain.com
- Alias:
  - points a hostname to an AWS resource (app.mydomain.com -> blabla.amazonaws.com)
  - works for BOTH, NON-ROOT and ROOT domains
    - ✅ mydomain.com
    - ✅ something.mydomain.com
  - free of charge
  - native health check

## Alias Records

- Maps a hostname to an AWS resource
- Extension of DNS functionality
- Automatically recognizes changes in the resource's IP addresses

```
                                    | Record name | Type | Value                                      |
Route 54 -> alias record enable ->  | example.com | A    | MyALB-1245....eu-east-1b.elb.amazonaws.com | -> MyALB-1245....eu-east-1b.elb.amazonaws.com [AWS-managed = IP addresses might change] -> ALB
```

- Unlike CNAME, it can be used for the top node of a DNS namespace (Zone Apex), ex: example.com
- Alias record is always of type A/AAAA for AWS resources (ipv4/ipv6)
- Can't set TTL -> aws does this automatically

### Alias Records targets

- Elastic load balancers
- CloudFront distributions
- API gateway
- Elastic Beanstalk environments
- S3 websites
- VPC interface endpoints
- Global accelerator
- Route 53 record in the same hosted zone

> You can't set an ALIAS record for an EC2 DNS name

## Hands on

- Create record
- On route traffic to:
  - check `alias`
  - this is better than CNAME and it's aws native
  - select the type of alias, the region and the load balancer

- How do you create for the root?
  - create record
  - on record name, don't add anything
  - check the `alias` checkbox
  - record type A or AAAA
  - point to an ALB/CLB
  - select the region
  - select the load balancer
