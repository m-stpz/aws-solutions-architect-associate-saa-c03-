# Health checks

- HTTP health checks are only for public resources
- Health check -> Automated DNS failover:
  1. Health checks that monitor and endpoint (application, server, other AWS resource)
  2. Health checks that monitor other health checks (calculated health checks)
  3. health checks that monitor CloudWatch (CW) alarms (throttles of dynamodb, alarms on RDS, custom metrics)
  - full control
  - helpful for private resources
- Health checks are integrated with CW metrics

```
              amazon route 53
                    |
              ----------------
health check |               | health check
          us-east-1       eu-west-1
             |                |
            ALB               ALB
      auto scaling group    auto scaling group
      EC2 instance          EC2 instance
```

## Monitor endpoint

- About 15 global health checkers will check the endpoint health
  - Healthy/unhealthy threshold - 3 (default)
  - Interval - 30s (can set to 10s, higher cost)
  - Supported protocol: HTTP, HTTPS and TCP
  - If > 18% of health checkers report the endpoint is healthy, route 53 considers it health
    - else, unhealthy
  - Ability to choose which locations you want route 53 to use
- Health checks pass only when the endpoint returns with 2xx and 3xx status codes
- They can be setup to pass/fail based on the text in the first 5120 bytes of the response
- Configure router/firewall to allow incoming requests from route 53 health checkers
