# Routing policy

- Define how route 53 responds to DNS queries
- Careful with the word "routing"
  - not the same as LB routing, which routes traffic
  - DNS doesn't route any traffic, it only responds to DNS queries

## Policies

### Simple

- single resource per record or returns multiple random IP addresses for basic client-side round-robin
  - doesn't support health checks for traffic shifting
- route traffic to a single resource
- can specify multiple values in the same record
- if multiple values are returned, a random one is chosen by the client

```
# single value

client --- foo.example.com ---> Amazon
       <--- 12.34.56.78 ------- route 53


# multiple values: client chooses randomly

client --- foo.example.com ---> Amazon
       <--- 12.34.56.78 ------- route 53
            11.22.33.44
            99.88.77.66
```

- when alias is enabled, specify only one AWS resource

### Weighted

- routes traffic across multiple endpoints based on assigned % weights
  - 80% for v1 and 20% for v2 for canary deployments or gradual rollouts
- control the % of requests that go to each specific resource
- assign each record a relative weight
  - weights don't need to sum up to 100

```
traffic (%) = weight for a specific record / sum of all the weights for all records
```

- DNS records must have the same name and type
- Can be associated with health checks
- Use cases: load balancing between regions, testing new application versions...
- weight = 0 -> resource won't receive traffic
- all records weight = 0 -> all records return equally

### failover

- uses health checks to implement active-passive failover
  - queries route to primary endpoint until it becomes unhealthy
  - then route 53 automatically switches DNS responses to secondary/DR endpoint

### Latency-based

- Directs users to AWS region with lowest network latency for that specific user
- Redirects the user to the smallest possible latency to the resource
- Very helpful when latency for users is a prio
- Latency is based on traffic between users and AWS regions
- As of know, when adding the latency based routing, you need to specify the region of the IP
  - AWS doesn't recognize it automatically as of now

### geolocation

- traffic is routed based on the geographic location of that user
  - useful for localizing content, language selection, or legal compliance

### geoproximity

- traffic is routed based on the geographic location of users and resources
  - bias parameter = expands/shrinks physical traffic radius directed to a specific region

### multi-value answer

- returns multiple healthy IP addresses selected at random
  - supports health checks to filter out failed endpoints

### IP-based

- routes traffic based on client CIDR blocks
  - useful for optimizing traffic from specific ISPs or private corporate subnets
