# DNS

- Domain Name System
- Translates human-readable hostnames into machine IP addresses
- Like a phone book which connects the person's name with his/her phone
- DNS is the backbone of the internet

## Terminology

- Domain Registrar: Route 53, GoDaddy, ...
- DNS records: A, AAAA, CNAME, NS, ...
  - individual config instructions stored in a db that tells DNS clients how to handle traffic for a specific name
  - `A` record: maps a hostname to ipv4
  - `AAAA` record: maps a hostname to ipv6
  - `CNAME` (canonical name): maps one hostname (alias) to another (ex: app.example.com -> lb.aws.com)
  - `NS` (name server): specifies which servers have authoritative DNS records for that domain
- Name server: resolves DNS queries (authoritative or non-authoritative)
  - specialized server that answers DNS lookups
  - authoritative: holds actual master copy of your DNS zone
  - non-authoritative: caches answers and queries other servers on behalf of client devices
- Zone file: contains DNS records
  - plain text file hosted on a name server that has all DNS records mapping to specific domain/subdomain
- Top level domain (TLD): .com, .us, .io, .gov, .org, ...
- Second level domain (SLD): amazon, google -> what comes before the TLD
- Sub domain: a child domain created under an SLD to separate environments (`api`, `dev`)
- FQDN (fully qualified domain name)
  - [sub domain] + SLD + TLD + [.]
- URL: uniform resource locator: complete address to access a resource on the web
  - protocol + [sub domain] + SLD + TLD + [.]

## How DNS works

```
[ Browser ] ──1. Query──► [ Local DNS / Resolver ]
                                │
                                ├──2. Query / 3. Referral──► [ Root DNS Server ]
                                ├──4. Query / 5. Referral──► [ TLD Server (.com) ]
                                └──6. Query / 7. Return IP─► [ Authoritative / SLD Server ]
                                │
[ Browser ] ◄─8. Return IP──────┘
     │
     └──────────9. HTTP Request (9.10.11.12)───────────────► [ Web Server ]
```

1. browser requests the website
   - is there on local cache?
     - if not found, query the local DNS (provied by ISP [Internet service provider]/internal network)
2. query the root dns server (managed by ICANN)
   - local dns server asks root server for location of `example.com`
3. root sends to TLD server
   - root server doesn't know the full domain's IP, but knows `.com`
   - sends to TLD server
4. query the TLD server
   - local dns server queries the `.com` TLD server for `example.com`
5. TLD sends to registrar's name servers
   - TLD server responds with authoritative name server for `example.com`
6. query the SLD / authoritative server
7. final IP resolution and caching
   - SLD returns the final record containing the IP address
   - local DNS server caches this result for some TTL
   - delivers to your browser
8. direct connection
   - browser connects to the web server over HTTP/HTTPS to load the page
