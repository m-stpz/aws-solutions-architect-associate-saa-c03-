# Route 53

- Highly available, scalable, fully managed and authoritative DNS
  - authoritative: the customer (you) can update the DNS records
- Route 53 is also a domain registrar
- Ability to check the health of your resources
- The only AWS service with 100% availability SLA
  - SLA = service level agreement
    - formal contract between a software/service provider and a customer that defines the expected level of service
- Why the name Route 53?
  - 53 is a reference to the traditional DNS port

- Route 53 performs 3 main functions:

1. domain registration
2. authoritative DNS resolution
3. health checking / traffic management

## Records

- How you want to route traffic for a domain
- Each record contains:
  - domain/subdomain name: e.g., example.com
  - record type: ex: A or AAAA
  - value: ex: 12.34.56.78
  - routing policy: how route 53 responds to queries
  - TTL: amount of time the record cached at DNS resolvers
    - "client, cache this result for the time of the TTL"
      - it's fine to have a long TTL given that we don't expect the domain to change
    - high: 24h
      - less traffic on route 53
      - possibly outdated records
    - low: 60s
      - increased traffic on route 53 ($$)
      - records at outdated for less time
      - easy to change records
    - except for alias records (CNAME), TTL is mandatory for each DNS record
- Route 53 supports the following DNS record types:
  - must know: A / AAAA / CNAME / NS
  - advanced: CAA / DS / MX / NAPTR / PTR / SOA / TXT / SPF / SRV

### Record types

- A: maps a hostname to ipv4
- AAAA: maps a hostname to ipv6
- CNAME: maps a hostname to another hostname
  - target is a domain name which must have an A or AAAA record
  - can't create a CNAME record for the top node of a DNS namespace (zone apex)
    - ex: you can't create an alias for example.com, but you can for www.example.com
- NS: name servers for the hosted zone
  - control how traffic is routed for a domain

### Hosted zones

- Container for records that define how to route traffic to a domain and its subdomains

- Public hosted zones: contains records that specify how to route traffic on the internet (public domain names)
  - `application1.mypublicdomain.com`
- Private hosted zones: contains records that specify how to route traffic within one or more VPCs (private domain names)
  - `application1.company.internal`

- Pay $0.5 per month per hosted zone

## Hands on

1. Registering a domain

- Register domains
  - $12 a year
- You can select the duration + also auto-renew
- Once it's registered, go to `hosted zones`

2. Creating a record

- Go to route 53 / hosted zones / <domain> / create record
- Then type
  - record name, record type, value, TTL, routing policy
    - the value is the IP of the instance

3. creating an ec2 instance to route

- create your instance (also in different regions)
  - ex:
    - us-east-1
    - eu-central-1
    - ap-southeast-1
- launch load balancer

## Route 53 vs. load balancer

- What's the relationship of Route 53 and load balancer?
- Route 53: global dns layer
  - global routing
  - latency / geolocation / failover
  - decides which IP address/ALB endpoint to return to the client browser
  - solves cross-region routing:
    - directs European users to ALB in frankfurt and american users to ALB in virginia
      - based on latency or geography
- load balancer: regional traffic and instance-level layer
  - regional routing
  - operates inside a SINGLE region

> Route 53 is the airport flight dispatcher: it looks at the world map, checks if airports (regions) are open, and directs your plan to land at the correct regional airport
> ELB is the ground taxi director at the airport: once the plan lands in that specific airport (region), it directs it to an open terminal gate (healthy EC2 instance)
