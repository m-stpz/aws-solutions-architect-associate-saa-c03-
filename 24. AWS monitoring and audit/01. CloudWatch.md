# CloudWatch

- monitoring and observability service
- collects and tracks operational data in the form of logs, metrics, and events

## CloudWatch metrics

- provides metrics for every service on AWS
- metric is a variable to monitor
  - CPUUtilization, NetworkIn...
- metrics belong to namespaces
- dimension is an attribute of a metric
  - instance id, environment, etc
- up to 30 dimensions per metric
- metrics have timestamps
- can create CloudWatch dashboards of metrics
- can create CloudWatch custom metrics

### Metric streams

- stream CloudWatch metrics to a destination, with near-real-time delivery and low latency
  - kinesis data firehose [and then its destinations]
  - 3rd party service provider: datadog, dynatrace, new relic, splunk, sumo logic...
- option to filter metrics to only stream a subset of them

## CloudWatch logs

- centralized log management service
- ingests, aggregates, stores, and allows queries on log data

- log groups: arbitrary name, usually an application
- log stream: instances within application / log files / containers
- can define log expiration policies: never expire, 1 day to 10 years
- cloudwatch logs can send logs to:
  - s3 [exports]
    - log data can take up to 12h to become available for export
  - kinesis data streams
  - kinesis data firehose
  - aws lamdba
  - opensearch
- logs are encrypted by default
- can setup KMS-based encryption with your own keys

### CloudWatch logs sources

- SDK, CloudWatch logs agent, CloudWatch unified agent
- Elastic beanstalk: collections of logs from application
- ECS: collection from containers
- AWS lambda: collection from function logs
- VPC flow logs: VPC specific logs
- API gateway
- CloudTrail based on filter
- Route 53: log DNS queries

### CloudWatch logs - Hands on

- CloudWatch / Log management
  - see existing groups
  - create log group

- CloudWatch / alarms
  - Create an alarmn
  - given a specific, determined value, you can have alarms that will inform you how your system is behaving

### CloudWatch logs for EC2

- by default, no logs from your EC2 machine will go to CloudWatch
- you need to run a CloudWatch agent on EC2 to push the log files you want
- IAM permissions need to be correct
- CloudWatch log agent can be setup on prem too

```
  [cloudwatch logs]
  |             |
CloudWatch    CloudWatch
Logs agent    logs agents
Ec2 instance  EC2 instance
```

### CloudWatch alarms

- Alarms are used to trigger notifications for any metric
- varions options
  - sampling, %, max, min, etc
- alarm states:
  - OK
  - INSUFFICIENT_DATA
  - ALARM
- Period:
  - length of time in s to evaluate the metric
  - high resolution custom metrics: 10s, 30s, or multiples of 60s

- Alarms can be created based on CloudWatch logs metrics filters

```
| CloudWatch           |  alert
| CW Logs ---- CW Alarm| ------> SNS
```

- We can test alarms and notifications through the CLI

#### CloudWatch alarms targets

- EC2 instance: stop, terminate, reboot, or recover
  - status check
    - instance status
    - system status
    - attached EBS status
  - recovery
    - same private, public, elastic IP, metadata, placement group

```
            monitor             alert
EC2 instance -------> CW alarm -----> SNS topic
   |                     |
    ---------------------
        ec2 instance recovery
```

- EC2 auto scaling group: trigger auto scaling action
- SNS: send notification to SNS
  - from which we can do pretty much anything

#### Composite alarms

- CloudWatch alarms are on a single metric
- Composite alarms allows us to monitor state of multiple other alarms
  - AND / OR conditions
- helpful to reduce "alarm noise" by creating complex composite alarms

```
                                          composite alarm
ec2 instance ---| ---> monitor CPU  -----|  CW alarm - A |   ----> [if CW alarm A AND B]
                | ---> monitor IOPS -----|  CW alarm - B |                  |
                                                                       trigger SNS
```

### CloudWatch network synthetic monitor

- Monitor and detects network issues between your apps hosted on AWS and you-prem data center
- Identify any network performance degradation, ex: packet loss, latency, jitter...
- No agents required to be installed
- Tests ICMP or TCP traffic to IPv4/IPv4 on-premises destinations through direct connect or S2S VPN connections
- publishes data to CW metrics

```
| AWS Cloud                     |
| CW metrics | Private subnet | |
|            |  EC2 instance  | |
            |
            |
  DX connection or VPN connection
            |
     | Corporate data center |
     |     server            |
```

## CloudWatch insights:

### container insights

- collect, aggregate, summarize metrics and logs from containers
- available for containers on...
  - ECS: elastic container service
  - EKS: elastic kubernetes service
  - Kubernetes platforms on EC2
  - fargate [both for EC2 and EKS]

### lambda insights

- monitoring and troubleshooting solution for serverless applications running on AWS lambda
- collects, aggregates, and summarizes
  - system-level metrics including CPU time, memory, disk, and network
  - diagnostic information such as cold starts and lambda worker shutdowns
