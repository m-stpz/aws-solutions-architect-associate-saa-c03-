# Common serverless architectures

## 1. The sync 3-tier web api / API pattern

baseline pattern for SPAs, mobile aps, CRUD APIs

```
[ Browser / Mobile Client ]
            │
            ▼
    [ Amazon API Gateway ]
    (JWT validation, throttling, caching)
            │
            ▼
    [ AWS Lambda Functions ]
    (CRUD operations / business logic)
            │
            ▼
    [ Amazon DynamoDB / Aurora Serverless ]
```

- Workflow
  - API gateway validates client tokens [via cognito/custom lambda authorizers]
    - routes HTTP methods
    - sync invoke individual lambda functions

- Best for:
  - mobile application backends
  - SaaS REST APIs
  - lightweight microservices

## 2. Async decoupled worker pattern

Used to protect downstream dbs/external APIs from sudden bursts of incoming traffic

```
[ Producer: API Gateway + Lambda ]
                │
                ▼ (Pushes payload in ~50ms)
       [ Amazon SQS Queue ]
                │
                ▼ (Pulls in controlled batches of 1-10)
    [ Worker Lambda Function ]
                │
                ▼
       [ Relational DB / Third-Party API ]
```

- Workflow
  - Instead of writing directly to db, an ingest lambda places the request into an SQS queue and immediately returns `202 accepted` to the client
  - Worker lambda polls SQS with controlled concurrent limits
    - flattening high-traffic spikes into a steady processing stream

- Best for:
  - order checkout processing
  - billing systems
  - 3rd-party webhook ingestion

## 3. Pub/Sub & Fan-out pattern

Used when a single action needs to trigger multiple independent subsystems in parallel

```
                        [ Order Placed Event ]
                                     │
                                     ▼
                            [ Amazon SNS Topic ]
                                     │
         ┌───────────────────────────┼───────────────────────────┐
         ▼                           ▼                           ▼
[ SQS: Inventory Queue ]   [ SQS: Payment Queue ]    [ SQS: Email Queue ]
         │                           │                           │
         ▼                           ▼                           ▼
[ Inventory Lambda ]        [ Payment Lambda ]        [ Email Lambda ]
```

- Workflow
  - a producer publishes a message to a SNS topic
  - SNS fans out this message to multiple SQS queues [each tied to a specific microservice domain]
  - Each subscriber process the event independently
    - failures in one queue, don't affect the others

- Best for:
  - e-commerce order pipelines
  - audit logging
  - multi-service event broadcasting

## 4. Event-driven data streaming and object processing

Used to process files and data transformations without long-running background daemons

```
[ Client Upload ] ───> [ Amazon S3 Bucket ]
                              │
                              ▼ (ObjectCreated Event)
                     [ AWS Lambda Function ]
                              │ (Transforms / Extracts metadata)
                              ▼
                     [ DynamoDB + ElasticSearch ]
```

- Workflow
  - user uploads a file directly to s3 via pre-signed URLs
  - S3 emits an event `ObjectCreated` that triggers a lamabda function to perform some operation [ex: resize image, parse records]
  - then lambda writes to the db the processed end-result

- Best for:
  - document ingestion
  - image/video thumbnail generation
  - daily CSV ETL pipelines

## 5. Choreographed workflows via step functions [saga pattern]

Used when business process involve multi-step transactions, retries, branching logic, or human approval

```
            [ AWS Step Functions (State Machine) ]
                                  │
         ┌────────────────────────┴────────────────────────┐
         ▼ (Task 1)                                        ▼ (Catch / Retry)
  [ Lambda: Charge Card ] ──(Fail)─────────────────> [ Lambda: Rollback ]
         │ (Success)
         ▼ (Task 2)
  [ Lambda: Reserve Seat ]
         │ (Success)
         ▼ (Task 3)
  [ Lambda: Send Receipt ]
```

- Workflow
  - step functions coordinates:
    - execution state
    - tracks variables
    - implementes automated retry/backoff policies
  - if task 2 fails, step functions executes compensating transactions

- Best for:
  - multi-step checkouts
  - long running batch data pipelines
  - human-in-the-loop workflows
