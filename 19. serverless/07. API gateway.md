# API Gateway

- Fully managed reverse-proxy and API management service
- Sits between clients and backend services

```
        REST API              PROXY REQ          CRUD
client ---------> API gateway ---------> Lambda ---------> Dynamodb
```

- Lambda + API gateway: no infra to manage
- Support for websocket protocol
- Handles
  - API versioning [v1, v2...]
  - different environments [dev, test, prod...]
  - security [authentication and authorization]
  - API keys, req throttling
  - swagger / Open API import to quickly define APIs
  - transform and validate req/res
  - Generate SDK and API specifications
  - cache API responses

## Endpoint types

- Edge-optimized [default]: global clients or you don't want to manage your own CloudFront dist
  - requests are routed through the CloudFront edge locations [improved latency]
  - API gateway still lives in only one region
- Regional: good for req same region or when you want to place your own CloudFront dist [custom caching rules and WAF config]
  - for clients within the same region
  - could manually combine with CloudFront, then you'd have more control over caching strategies and dist
- Private: can only be access from VPC using an interface VPC endpoint [ENI]

## API gateway - Integrations

- Lambda function
  - invoke lambda func
  - easy way to expose REST API backed by lambda
- HTTP
  - expose HTTP endpoints in the backend
  - internal HTTP API on premise, ALB...
  - Why?
    - Add rate limiting, caching, user authentications, API keys, etc...
- AWS service
  - expose any AWS API through the API gateway
    - we can make any AWS service "public" through the API gateway
  - start an AWS step function workflow, post a message to SQS
  - why?
    - Add authentication, deploy publicly, rate control...

### API Gateway WebSocket APIs with AWS lambda

- Standard architecture for building serverless, bidirectoinal teal-time applications
- Traditional architectures, maintaining open websocket connections requires dedicated, long-running servers [eg. Node.js with socket.io or ec2 instance] to manage TCP states
- In this pattern, API gateway maintains the persistent connection
  - it invokes lambda function only when an event or message occurs

```
[ Client (Browser / App) ]
           │
           │ (1) Persistent WebSocket Connection (wss://...)
           ▼
┌────────────────────────────────────────────────────────┐
│               Amazon API Gateway                       │
│  - Holds open TCP state for up to 2 hours              │
│  - Parses incoming JSON action routes                  │
└──────┬──────────────────────┬───────────────────┬──────┘
       │                      │                   │
  (on $connect)          (on message)        (on $disconnect)
       │                      │                   │
       ▼                      ▼                   ▼
┌──────────────┐       ┌──────────────┐    ┌──────────────┐
│  Connect     │       │ Message      │    │ Disconnect   │
│  Lambda      │       │ Lambda       │    │ Lambda       │
└──────┬───────┘       └──────┬───────┘    └──────┬───────┘
       │                      │                   │
       ▼                      │                   ▼
┌──────────────┐              │            ┌──────────────┐
│ Store        │              │            │ Delete       │
│ ConnectionId │              │            │ ConnectionId │
└──────┬───────┘              │            └──────┬───────┘
       │                      │                   │
       └──────────────┐       │       ┌───────────┘
                      ▼       ▼       ▼
                [ Amazon DynamoDB Table ]
                (Stores active connectionIds)
                              │
                              ▼
        [ ApiGatewayManagementApiClient.postToConnection() ]
                              │
                              │ (2) Push outbound message back to client
                              ▼
                     [ Return to Client ]
```
