# Lambda Invocation from RDS vs. Event notification

## Native lambda invocation from RDS / Aurora: Data level

- Happens inside the DB engine, not the RDS engine
- Invoke lambda from within your db instances
- Allows to process data events from within a db

```
User ---> register [INSERT] ---> RDS db instance ---> lambda functions ----> send email -----> SES
  |                              [permissions]                                                   |
  |----------------------------------------------------------------------------------------------|
```

- Supported for RDS for postgres and aurora mysql
- Must allow outbound traffic to your lambda func from within db instance
- db instance must have required permissions to invoke the lambda func

- use cases
  - calling payment gateway/sending email when some action happens
  - real-time cache invalidation [evicting redis keys on data change]
  - data streaming/ETL to external microservices without polling the db

## RDS / Aurora event notification: Infra level

- Managed by RDS control plane, not the SQL engine
- Instead of the data level, it's more on the infra/db instance level [created/stopped/started...]
- No info about the data itself

- use cases
  - sending slack alerts during db failovers/outages
  - triggering automated post-snapshot actions
  - security compliance monitoring
