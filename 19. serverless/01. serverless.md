# Serverless

- New paradigm where devs don't have to manage servers anymore
- They just deploy code
- Initially serverless was applied to functions
  - it was FaaS: function as a service
  - however, nowadays it has grown to dbs, messaging, storage, etc
  - anything that is managed and allows you not to worry about the underlying server
- Serveless doesn't mean that there are NO servers, instead you don't manage/provision them
- Devs build and run applications without `___` the underlying virtual servers/containers
  - managing
  - patching
  - maintaining

## Core operational traits

- Zero server management: you never SSH into a host, install an OS, update packages, or manage runtimes
- Automatic, Elastic scaling: capacity scales automatically based on consumption
- Pay-for-value billing: no charge for idle compute
- Built-in high availability and fault tolerance: services operate natively across multiple AZs by default

## Serverless services in AWS

- Not just compute, an ecosystem across compute, storage, messaging and orchestration

- Compute
  - AWS lambda: ephemeral functions
  - AWS fargate: containers

- Storage and db
  - s3: object store
  - dynamoDB: serverless NoSQL
  - aurora serverless: auto-scaling relational db

- Integrations and messaging
  - API gateway: Rest/HTTP/WebSocket endpoints
  - EventBridge: serverless event bus
  - SNS: pub/sub push
  - SQS: message queuing

- State and orchestration
  - AWS step functions: visual state machines and workflow orchestration
