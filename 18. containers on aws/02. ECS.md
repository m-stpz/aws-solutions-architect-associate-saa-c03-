# ECS: Elastic container service

- AWS's fully managed container orchestration platform
- Handles the lifecycle of docker containers
  - when they run
  - keeping them healthy
  - connecting them to load balancers
  - scaling them

- When running containers on ECS, choose where the compute power comes from
  - this is determined by launch type

1. Fargate: serverless, AWS provisions and manages the compute
2. EC2 launch type: you provision, manage, and scale your own cluster of EC2 VMs

## Core terminology

- Task definition: the blueprint [json doc]
  - defines which docker images to pull
  - required CPU/memory
  - env variables
  - networking mode and ports

- Task: running instantiation of a task definition
  - one or more containers working together

- Service: orchestrator for tasks
  - if tasks crashes, service replaces it
  - registers running tasks to ALB target groups and handles auto-scaling

- Cluster: logical grouping of tasks, services, and compute capacity

## EC2 launch type

- You manage it
- Create an ASG of standard EC2 instances and register them into a ECS cluster

```
+---------------------------------------------------------------+
|                       ECS Cluster                             |
|                                                               |
|  [ EC2 Instance 1 (t4g.xlarge) ] [ EC2 Instance 2 (t4g.xlarge)]|
|  +-----------------------------+ +---------------------------+ |
|  |       ECS Container Agent   | |     ECS Container Agent   | |
|  +-----------------------------+ +---------------------------+ |
|  | [Task A]  [Task B]  [Task C]| | [Task A]  [Task D]        | |
|  | (Docker)  (Docker)  (Docker)| | (Docker)  (Docker)        | |
|  +-----------------------------+ +---------------------------+ |
+---------------------------------------------------------------+
```

- Here we control the VM, so we have some features that serverless fargate doesn't offer
  - bin-packing and cost optimization
  - tasks placement strategies and constraints
  - hardware customization for specific needs

## Fargate launch type

- Serverless
  - we don't need to provision the infra -> no ec2 instance to manage
  - we just create task definition
- AWS runs ECS tasks for you based on the CPU/RAM you need
- To scale, just increase the number of tasks

| Dimension              | ECS with EC2 Launch type                                                                       | ECS with Fargate                                                               |
| ---------------------- | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| Server management      | High [os patching, AMI updates, ec2 agent updates]                                             | None [100% serverless, zero OS access]                                         |
| Pricing model          | pay for the ec2 instances 24/7 [whether full or empty]                                         | Pay for vCPU/RAM used                                                          |
| GPU/machine learning   | supported (g4, g5, p4 instances)                                                               | Not supported for GPU-heavy acceleration                                       |
| Cold start             | fast (5-15s) if instances have free capacity and cached images                                 | slower (30-60s+), must provision microVM and pull image                        |
| Task placement control | Granular                                                                                       | Managed by AWS                                                                 |
| Best used for          | Large-scale production clusters with predictable base loads, GPU ML workloads, custom OS needs | Standard web APIs, microservices, background jobs, unpredictable spiky traffic |

## ECS - IAM Roles for ECS

- 3 distinct IAM roles

````
+--------------------------------------------------------------------------------+
| EC2 Instance (Only for EC2 Launch Type)                                        |
| [1. EC2 Instance Profile Role] -> Grants host VM permission to register to ECS |
|                                                                                |
|  +--------------------------------------------------------------------------+  |
|  | ECS Container Agent                                                      |  |
|  | [2. Task Execution Role] -> Grants agent permission to pull ECR & logs   |  |
|  +--------------------------------------------------------------------------+  |
|         |                                                                      |
|         v                                                                      |
|  +--------------------------------------------------------------------------+  |
|  | Application Container                                                    |  |
|  | [3. Task Role] ----------> Grants application code permission to S3/DB   |  |
|  +--------------------------------------------------------------------------+  |
+--------------------------------------------------------------------------------+```
````

| Aspect         | EC2 Instance profile role                                                        | ECS Task Execution Role                  | ECS Task Role                                    |
| -------------- | -------------------------------------------------------------------------------- | ---------------------------------------- | ------------------------------------------------ |
| role           | ecsInstanceRole                                                                  | executionRoleArn                         | taskRoleArn                                      |
| who uses it    | underlying EC2 VM, only relevant on EC2 launch type, not fargate                 | ECS infra/ECS container agent            | application code inside container                |
| when it's used | at the OS and VM boot level                                                      | before and during container setup        | while container is running                       |
| what it does   | Allows the ec2 instance and ecs containers to communicate with ECS control plane | grants ECS permissions to boot container | provides temp AWS credentials to the application |

## Load Balancers Integrations

- ALB: supported and works for most use cases
- NLB: recommended for high throughput / performance use cases
  - also pairs with private link
- CLB: supported, but not recommended
  - no advanced features
  - no fargate

## EC2 Data Volumes [Persistent Data]

- Allows us to have persistent/shared data in ECS

1. EFS: Shared multi-task storage
   - Both ec2 and fargate can use it
     - Fargate + EFS: fully serverless, scales automatically to PB
   - mounts EFS file system onto ECS tasks
   - tasks running in any AZ will share the same data in the EFS file system
   - use case: persistent multi-AZ shared storage for containers

```
ECS Cluster
    | ec2 instance |     | fargate      |
    | [container]  |     | [container]  | // each container mounts the EFS
    | [container]  |     | [container]  |
--------------
        |
    Amazon EFS
    [file system]
```

2. S3 files: mount s3 file systems onto ECS tasks
   - s3 bucket exposed as file system
   - works for fargate and eCS managed instances
     - ECS launch type IS NOT supported
   - changes sync automatically to s3 bucket
   - use case: containers needing shared file access to data existing in s3
